## 2. 시스템 구성

```text
[시뮬레이션]                                   [실물]
MuJoCo (pickplace_scene.xml)                   Jetson: top_camera_publisher(/top_cam) · arm_io(/real/joint_states)
   │ 관절각 q, 큐브 참값(+DR 노이즈)                │
   ▼                                               ▼ PC: cube_detector  (/cube_obs: x, y, yaw, valid)
observation.CubeEstimator ◀──── 같은 코드 ────▶ observation.CubeEstimator
   ▼                                               ▼
build_observation (28/30차원) ◀── 같은 코드 ──▶ build_observation
   ▼                                               ▼
SAC 정책 (policy_best.zip)    ◀── 같은 파일 ──▶ SAC 정책
   ▼ Action 5                                      ▼
controller.ActionMapper (IK)  ◀── 같은 코드 ──▶ controller.ActionMapper
   ▼ 관절 목표                                     ▼ /joint_targets
속도 제한 램프(env.cmd)       ◀── 같은 값 ────▶ arm_io 속도 제한 (joints.yaml max_vel_rad_s)
```

- 시뮬과 실물의 차이는 **입력의 출처(MuJoCo 참값 vs 카메라·서보)** 뿐이고, 관측 생성·추론·IK는 한 줄도 다르지 않다.
- 관절 속도 한계 `robot.max_joint_vel_rad_s`는 실물 `joints.yaml`의 `max_vel_rad_s`와 같게 둔다(0.35~0.60 rad/s). 실물에서 값을 바꾸면 시뮬 설정도 바꾸고 다시 학습한다.

## 3. 설계 (보고서 '설계 적절성' 20점 = 관측·Action·Reward·실물 대응 각 5점)

### 3.1 Observation — 실물에서 얻을 수 있는 정보만, 실물과 같은 방식으로

| 인덱스 | 내용 | 근거 |
|---|---|---|
| 0–5 | 관절각 6 | 서보 엔코더로 실측 가능 |
| 6–8 | 제어점 XYZ (FK) | 관절각에서 계산 → 실물 동일 |
| 9–10 | 그리퍼 yaw (sin 2φ, cos 2φ) | 2손가락 그리퍼는 180° 대칭 |
| 11–13 | 큐브 XYZ **추정값** | 카메라는 높이를 모름 → 놓여 있으면 휴지 높이, 잡혀 있으면 제어점 + 잡을 때 오프셋 |
| 14–15 | 큐브 yaw: 기본 (sin θ, cos θ) / 개선 (sin 4θ, cos 4θ) | **비교 A의 핵심 변수** |
| 16–24 | 큐브−제어점, 목표−큐브, 목표−제어점 | 상대 벡터가 일반화에 유리 |
| 25–27 | 잡힘 추정(닫힘 명령인데 그리퍼 각 > 0.0 rad), 닫힘 명령, 남은 시간 비율 | 잡힘은 **접촉 센서 없이 서보 각도로만** 판단 → 실물 동일 |
| 28–29 (개선) | 잡기 정렬 오차 fold45(θ−φ), 놓기 정렬 fold45(θ) | 손목을 얼마나 돌릴지 바로 알려 줌 |

- 실물 카메라(minAreaRect)는 yaw를 [-45°, 45°)로만 준다. 개선안은 시뮬에서도 같은 접힌 값을 받으므로 **실물 입력 분포와 일치**한다(기본안은 시뮬에서만 ±180°를 받음 → 이것도 비교 A의 해석 포인트).

### 3.2 Action — 말단 증분 + 손목 + 그리퍼

- `[Δx, Δy, Δz] × [8, 8, 6] mm`, `Δyaw × 0.15 rad`, 그리퍼 `> 0 닫기 (−0.10 rad) / ≤ 0 열기 (0.55 rad ≈ 손가락 간격 50 mm)`.
- 제어점 = gripperframe + 18 mm(닫힘 축) − 5 mm(접근 축). 고정 손가락 안쪽 면에서 큐브 반변 12.5 mm + 여유 5.5 mm → 내려갈 때 고정 손가락이 큐브를 치지 않음(실측으로 정한 값).
- IK: pan·lift·elbow·wrist_flex 4관절, 위치 3 + "접근 축이 아래" 1을 감쇠 최소자승으로. 도달 불가 요청(IK 오차 > 12 mm)은 팔을 제자리에 둔다 → 이상 자세 방지.
- 작업면 아래 금지(z ≥ 4 mm), XY 작업 영역 클램프, 관절 속도 제한 → '동작 안정성' 3점 근거.

### 3.3 Reward — 단계형 최댓값 + 꼼수 차단

| 단계 | 값 | 조건 |
|---|---|---|
| reach | 0.25·(1−tanh(10·d)) | 항상 |
| grasp | 0.35 | 양 손가락 접촉 |
| lift | 0.50·(0.7~1.0) | 잡힘 + 작업면 비접촉 + 밑면 > 2 mm |
| carry | 0.80·(0.6~1.0) | **들린 상태에서만** 목표까지 거리 |
| place | 1.00 | 잡은 채 목표 안에서 착지 |
| release | 1.30 + 0.5·유지 비율 | **해제 + 목표 안 + 한 번이라도 들었음** |
| 정렬(개선) | ±0.10 | 접근 중 cos 4(θ−φ), 목표 근처 운반 중 cos 4θ |
| 밀기 | −20/m | 잡지 않은 채 로봇이 큐브를 움직인 거리 |
| 종료 | 성공 +50, 영역 밖 −10 | |

- 단계 보상을 **더하지 않고 최댓값**으로 → 앞 단계 보상을 모으며 버티는 전략이 이득이 없음.
- release > place 이므로 "잡은 채 목표 위에 머무르기"보다 "놓기"가 항상 유리.

### 3.4 실물 대응 (sim2real)

| 문제 | 대응 | 근거 수치 |
|---|---|---|
| 픽셀 → base_link | 체커 꼭짓점 11점 호모그래피 (`calibrate_homography.py`), 재투영 오차 표로 기록 | 목표: RMS < 2 mm |
| 큐브 윗면 시차 | `(1 − h/H_cam)` 보정 | 시뮬 카메라: 3.0 → 1.7 mm |
| 그리퍼가 큐브를 가림 | 잡힘 중에는 카메라 대신 제어점+오프셋으로 추정, 검출 실패 시 마지막 값 유지 | DR에서 가림·실패 재현 |
| 오검출·튐 | 면적 범위, ROI, 프레임 간 3 cm 이상 점프 무시, 지수 평활 | |
| 서보 속도·응답 차이 | 시뮬 관절 속도 한계 = arm_io 한계, DR로 강성 ±20 %·속도 ±15 % | |
| 마찰·질량 | DR 마찰 ±30 %, 질량 ±20 % | |
| 카메라 지연 | DR 0~2 스텝 지연 | |
| 안전 | 관절 상태 0.3 s 끊기면 정지, 측정 대비 0.35 rad 이상 목표 차단, 준비 자세가 아니면 start 거부 | |

## 5. 비교실험 계획 (보고서 '비교실험' 10점)

### 5.1 고정할 조건 (두 방법 모두 동일)
알고리즘·하이퍼파라미터, 학습 스텝(1.5 M), 학습 seed, 커리큘럼(시작 범위 30 % → 학습 50 % 시점에 100 %), 평가 seed(공식 0~9 + 추가 1000~1099), 환경 버전(`task.yaml` 커밋 해시를 run_config에 남김).

### 5.2 비교 A — yaw 대칭 관측

| | 기본 `exp_A_base` | 개선 `exp_A_sym` |
|---|---|---|
| 큐브 yaw 입력 | (sin θ, cos θ), θ∈[-π, π] | (sin 4θ, cos 4θ), 접힌 θ |
| 추가 관측 | 없음 | 잡기·놓기 정렬 오차 |
| 정렬 보상 | 없음 | ±0.10 |

지표: ① 성공률(공식 10 + 추가 100) ② yaw 8구간별 성공률 ③ 성공 회차 놓은 위치 여유(mm) ④ 학습 곡선 ⑤ 종료 원인 분포.
가설: 기본은 특정 yaw 구간(손목을 크게 돌려야 하는 구간)에서 잡기 실패가 많고 여유가 작다.
가능하면 학습 seed 2개(7, 8)씩 → 막대에 범위 표시. 시간이 부족하면 seed 1개.

### 5.3 비교 B — Domain Randomization

| | 기본 = A 개선 정책 | 개선 `exp_B_dr` |
|---|---|---|

평가 환경 2개: 공칭(`nominal`)과 **노이즈 시험 환경**(`config/eval_noise.yaml`, 학습 범위보다 약간 넓음). 실물 예비 시험 각 정책 4~5회(12/10~12 배정일).

## 8. 실물 시험 프로토콜 (검사 당일과 리허설 동일)

1. Jetson: `arm_io`, `top_camera_publisher` 실행 · PC: `cube_detector`, `policy_runner` 실행 (같은 `ROS_DOMAIN_ID`).
2. `rqt_image_view /cube_debug`로 큐브 검출 확인 → 큐브를 빨간 점에 두고 (0.270, 0.000) ± 3 mm 인지 확인.
3. 토크 ON → `/pickplace/ready` → 그리퍼 열림·준비 자세 확인.
4. 평가자가 큐브 배치 → `/pickplace/start` → **손대지 않음**(개입·재시작 시 0점).
5. 30 s 후 자동 정지 → 로그 파일 이름 메모 → `/pickplace/ready`로 다음 회차 준비.
6. 금지: 시험 중 정책·파라미터·HSV·호모그래피 변경. 조명 변화 대비는 리허설 때 HSV 여유를 둬서 해결.
