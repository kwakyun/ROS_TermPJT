# 실습 진행 가이드 — 설치부터 검사 당일까지 명령 순서

> PC: Windows + WSL2 Ubuntu 22.04 (11주차와 같은 환경), Jetson: 9주차 `arm_io`·7주차 `top_camera_publisher`가 빌드된 상태.
> 프로젝트 위치 `~/termproject`, 가상환경 `~/termproject/.venv`. 모든 PC 명령은 프로젝트 루트에서 실행한다.

```text
0 설치 → 1 검증(4종) → 2 학습(A_base, A_sym) → 3 평가·비교 A → 4 실습실 1차(보정·실측)
→ 5 DR 학습·비교 B → 6 실습실 2차(실물 예비 시험) → 7 최종 동결·영상 → 8 실습실 3차 리허설 → 9 제출 → 검사
```

## 0. 설치 (PC, 각자 1회)

```bash
# 코드 배치: 전달받은 termproject 폴더를 WSL 홈으로 복사
cp -r /mnt/d/Projects/RosTermPJT/termproject ~/termproject      # 경로는 각자 위치로
cd ~/termproject
sudo apt update && sudo apt install -y python3.10-venv libgl1 libglfw3 libegl1
python3 -m venv .venv
source .venv/bin/activate
export PYTHONDONTWRITEBYTECODE=1
python3 -m pip install --no-cache-dir torch==2.9.1 --index-url https://download.pytorch.org/whl/cpu
python3 -m pip install --no-cache-dir -r requirements.txt
python3 -m pip check
```


## 2. 학습 (역할 A 주관)

```bash
# 동작 확인용 짧은 학습 (5분 내외): 오류 없이 runs/smoke 가 생기는지
python -m pickplace.train --exp config/exp_A_sym.yaml --run smoke --steps 20000

# 비교 A 본 학습 (각 1.5 M 스텝, 코어 수만큼 --n-envs)
nohup python -m pickplace.train --exp config/exp_A_sym.yaml  --run A_sym_s7  --n-envs 8 > logs_A_sym_s7.txt 2>&1 &
nohup python -m pickplace.train --exp config/exp_A_base.yaml --run A_base_s7 --n-envs 8 > logs_A_base_s7.txt 2>&1 &
# 학습 seed 추가(가능하면): --seed 8 --run A_sym_s8 / A_base_s8
```

진행 확인:
```bash
tail -f logs_A_sym_s7.txt | grep eval          # [eval] t=... curriculum=... success=... stage=...
tensorboard --logdir runs                       # 브라우저 localhost:6006 → rollout/ep_rew_mean, success_rate
```
- `stage`(검증 회차의 평균 최고 단계: 0 접근 · 1 잡기 · 2 들기 · 3 놓기 · 4 해제 · 5 성공)가 오르는지 본다.
- 첫 학습에서 **초당 스텝 수**를 기록하고 일정(01 문서 6장)을 보정한다.
- 50만 스텝까지 `stage < 1`이면 01 문서 9장 대책 ①부터 적용(기본·개선 **둘 다** 같은 변경으로 재학습).

산출물: `runs/<run>/policy_best.zip`(검증 최고), `policy_final.zip`, `eval_history.csv`, `monitor/`, `run_config.yaml`(사용한 모든 설정).

### 4.6 그리퍼·관절 실측 (C)
```bash
ros2 service call /robot/set_torque std_srvs/srv/SetBool "{data: true}"
# 그리퍼만 움직여 보기 (다른 관절은 현재 목표 유지)
```

- 값이 시뮬과 크게 다르면 `config/task.yaml > robot` 수정 → `scripted_check` → A에게 재학습 요청.

## 6. 실습실 2차 (12/10~12) — 실물 예비 시험 (역할 C 진행)

PC 터미널 4개 (4.2 준비 후):
```bash
# T1 검출
python3 real/cube_detector.py --config real/config/real.yaml
# T2 정책 (회차마다 다시 띄울 필요 없음)
python3 real/policy_runner.py --config real/config/real.yaml --run A_sym_s7

# T4 조작
ros2 service call /robot/set_torque std_srvs/srv/SetBool "{data: true}"
ros2 service call /pickplace/ready std_srvs/srv/Trigger      # 준비 자세(그리퍼 열림)
#   → 큐브 배치 (다른 팀원이 무작위 위치·방향, 위치를 기록)
ros2 service call /pickplace/start std_srvs/srv/Trigger      # 회차 시작, 30 s 후 자동 정지
ros2 service call /pickplace/stop  std_srvs/srv/Trigger      # 위험할 때만
```
- 회차 기록표(팀 자체 채점, TERM_PROJECT 2.2 기준): 회차 · 배치 · 도달 단계 · 완성도(5) · 안정성(3) · 관측·제어 대응(2) · 로그 파일 이름 · 메모.
- A_sym, B_dr 각 4~5회 → 01 문서 5.4 규칙으로 비교.
- 실패하면 `logs/real/<시각>_trialN.csv`에서 `cube_visible`(관측 끊김), `grasped_est`(잡힘 추정), `ik_error`(도달 불가), 행동 열(`a_grip`이 언제 바뀌는지)을 본다 → `logs/problems.md`에 기록.

> 실물 없이 미리 연결만 시험하려면: 9주차 `mujoco_compare.launch.py`의 시뮬 브리지를 띄우고 `real.yaml > ros.joint_state_topic`을 시뮬 상태 토픽으로 바꿔 runner 를 실행한다(토픽 이름은 `ros2 topic list`로 확인).

## 10. 자주 나는 문제

| 증상 | 원인 | 해결 |
|---|---|---|
| `gladLoadGL error` (영상·렌더링) | 화면 없는 OpenGL | `MUJOCO_GL=egl` (안 되면 `sudo apt install libosmesa6` 후 `MUJOCO_GL=osmesa`) |
| `ModuleNotFoundError: pickplace` | PYTHONPATH 미설정 | `export PYTHONPATH=~/termproject` |
| `FileExistsError: runs/...` | 같은 run 이름 | 이름 변경(덮어쓰기 방지 설계) |
| `rclpy` import 실패 | ROS 미설정 | venv 활성화 **전에** `source /opt/ros/humble/setup.bash` |
| `/top_cam` 이 PC에서 안 보임 | 도메인·네트워크 | 양쪽 `ROS_DOMAIN_ID`, `ROS_LOCALHOST_ONLY=0`, 같은 공유기, 방화벽(4주차 troubleshooting) |
| start 가 "not at ready pose" | 준비 자세 미도달 | `/pickplace/ready` 후 2~3초 기다림, 토크 ON 확인 |
| 실물 팔이 거의 안 움직임 | arm_io 토크 꺼짐 / 목표 거부 로그 | `/robot/set_torque true`, Jetson 로그의 "명령 거부" 확인(관절 한계) |
| 검출이 깜빡임 | HSV 범위·조명 | `tune_hsv.py` 재조정, `min_area_px`, ROI |
| 큐브 위치가 일정하게 밀림 | 시차·호모그래피 | `--camera-height` 재측정, 보정 다시, 4.5 표로 편향 확인 |
| 잡았는데 `grasped_est` 0 | 그리퍼 각 임계 불일치 | 4.6 실측으로 `grasp_detect_rad` 조정(→ 재학습 필요) |
