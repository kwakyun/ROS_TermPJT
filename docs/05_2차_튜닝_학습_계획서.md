# 2차 튜닝 학습 계획서 (잡기 성공률 개선 및 비교 A 재실험)

> 1차 본 학습(`A_base_s7`, `A_sym_s7`)의 150만 스텝 완주 결과 분석과 `grasp_fail` 국소해 원인 진단을 바탕으로, 계획서 9장(위험과 대책)에 의거한 2차 튜닝 및 재학습 계획을 정리한 문서입니다.

---

## 1. 1차 학습 결과 및 원인 분석

### 1.1 1차 학습 종합 결과 (`table.md`)
| 모델 | 에피소드 보상 (`ep_rew_mean`) | 공식 10회 성공률 | 추가 100회 성공률 | 주 종료 원인 | 평균 최고 단계 (`mean_max_stage`) |
|---|:---:|:---:|:---:|:---:|:---:|
| `A_base_s7` | 38 $\rightarrow$ 121 | 0 / 10 (0.0%) | 0.0% | `grasp_fail` 110회 | 0.033 ~ 0.20 |
| `A_sym_s7` | 38 $\rightarrow$ **185** | 0 / 10 (0.0%) | 0.0% | `grasp_fail` 110회 | 0.000 ~ 0.03 |

### 1.2 핵심 원인 진단 (코드 및 로그 기반)
1. **보상 구조의 국소해 (Reward Hacking / Hovering Trap)**:
   - `pickplace/reward.py`와 `config/task.yaml` 분석 결과:
     - `sym` 모델이 큐브를 집지 않고 위에서 방향만 맞춘 채 배회(`Hover`)할 때: `reach(0.25) + align_grasp(0.10)` = **+0.35 / step** (600스텝 시 최대 약 210점 $\rightarrow$ 실제 수렴 보상 185와 일치).
     - 반면 실제로 그리퍼를 닫아 큐브를 잡았을 때(`grasped=True`): `align_grasp` 항이 비활성화(`not s["grasped"]` 조건)되면서 `grasp(0.35) + 0` = **+0.35 / step**.
     - **문제점**: 큐브를 실제로 잡아도 보상 증가량이 전혀 없으며, 도리어 큐브를 건드리다 밀어버리면 `push_penalty_per_m = 20.0`의 큰 감점만 받게 됨.
     - 그 결과 개선 모델(`A_sym_s7`)이 큐브를 건드리지 않고 위에서 각도만 맞추는 상태에 갇혀 `A_base_s7`보다 오히려 낮은 단계(0.00 vs 0.17)를 기록함.
2. **그리퍼 닫힘 명령 지연과 SAC 탐색 붕괴**:
   - `controller.py`의 관절 속도 제한(`0.60 rad/s`, 제어 주기 `dt=0.05s`)에 따라 그리퍼가 완전히 닫히는 데 최소 15~22스텝 연속으로 `a[4] > 0`이 유지되어야 함.
   - SAC의 순수 무작위 탐색(Random Exploration)으로 이 연속 행동을 우연히 찾아내기 전에 `ent_coef`(엔트로피 계수)가 `0.85 $\rightarrow$ 0.00126`으로 빠르게 소멸되어 탐색이 굳어짐.
3. **`policy_best.zip` 갱신 로직 버그 (`train.py`)**:
   - `train.py`에서 `if r["success_rate"] > self.best:`만 검사함.
   - `self.best = -1.0`으로 시작하므로, 학습 극초반 5만 스텝 시점(21:42)에 `0.0 > -1.0`으로 인해 미학습 가중치가 `policy_best.zip`으로 저장된 이후 한 번도 갱신되지 못함.
4. **학습 효율 및 CPU 병목**:
   - 코어 14개 환경에서 8-env 병렬 프로세스 2개를 동시 실행하여 CPU 경합이 발생, 처리 속도가 ~105 fps로 낮아져 1.5M 스텝 완료에 약 4시간 소요됨.

## 3. 세부 개선 전략

### 3.1 보상 사다리(Reward Ladder) 재설계 (`config/task.yaml`)
큐브를 실제로 잡았을 때 확실한 보상 점프가 발생하도록 단계별 가중치를 상향:

| 보상 파라미터 | 1차 설정 | 2차 변경안 | 변경 의도 |
|---|---:|---:|---|
| `reach_scale` | 0.25 | **0.25** | 접근 단계 상한 유지 (Hover 보상 제한) |
| `align_weight` (`sym`) | 0.10 | **0.10** | 접근+정렬 최대치 0.35 유지 |
| `grasp` | 0.35 | **0.80** | 잡기 성공 시 **즉시 +0.45 이상 점프**하여 잡기 유도 |
| `lift` | 0.50 | **1.20** | 잡은 후 들어 올리기 단계로 강력 유인 |
| `carry` | 0.80 | **1.60** | 운반 보상 강화 |
| `place` | 1.00 | **2.00** | 목표 영역 안착 보상 강화 |
| `release` / `hold` | 1.30 / 0.50 | **2.50 / 1.00** | 최종 성공 단계 보상 최상위 유지 |
| `push_penalty_per_m` | 20.0 | **5.0** | 잡으려다 스치는 동작에 대한 과도한 위축 완화 |

### 3.2 커리큘럼 범위 완화 (`config/task.yaml`)
- `start_scale`: `0.3 $\rightarrow$ 0.1` (초기 위치 및 yaw 범위를 10% 영역으로 집중하여 초반 잡기 경험을 빠르게 확보)
- `full_at_fraction`: `0.5 $\rightarrow$ 0.6` (전체 범위 확장 속도를 완만하게 하여 잡기 안정화 시간 확보)

### 3.3 SAC 리플레이 버퍼 시연 초기화 (대책 ④ 구현, `train.py`)
- 계획서 9장 대책에 따라 `--demo-episodes 30` 옵션을 `train.py`에 추가.
- 공식/검증 시드와 겹치지 않는 별도 시드(`20000+`)에서 `scripted_check`의 성공 궤적 30회(약 6,000~7,000 스텝)를 수집하여 SAC 리플레이 버퍼(100만 크기)의 0.7%를 사전 채움.
- **보고서 명시 사항**: 사전 시연 데이터는 버퍼 초기화용일 뿐이며, 신경망 가중치는 SAC 강화학습 알고리즘을 통해서만 학습됨을 기재.

### 3.4 학습기 코드 수정 및 최적화
1. **최고 모델 판정 기준 보완 (`train.py`)**:
   - `(success_rate, mean_max_stage)` 튜플 기준으로 최고 모델을 저장하도록 수정하여, 성공률이 0%인 구간에서도 더 높은 단계(lift, carry 등)에 도달한 가중치가 `policy_best.zip`에 정상 반영되도록 함.
2. **학습 속도 최적화**:
   - 두 모델을 동시 실행하지 않고 **단독 실행**하여 14코어 전체를 집중 (프로세스당 200~250 fps 확보, 1 run당 1.5~2시간으로 단축).
   - `gradient_steps: 1 $\rightarrow$ 2`로 조정하여 병렬 환경(8 envs) 데이터 수집 대비 신경망 업데이트 빈도 보강.

## 4. 단계별 실행 로드맵

```text
[Phase 0] 1차 결과 보존
   └─ runs/A_*_s7 및 reports/compare_A 원본 유지 (보고서 실패 원인 분석용)
          ↓
[Phase 1] 설정 및 코드 수정 / 단위 검증
   └─ task.yaml, train.py 수정 후 검증 4종 + smoke_v2 (2만 스텝) 확인
          ↓
[Phase 2] A_sym_v2 단독 학습 및 조기 검증 게이트
   └─ 30만 스텝 시점(약 30분) eval_history.csv 점검 (stage ≥ 1.0 확인)
   └─ 통과 시 150만 스텝 완주
          ↓
[Phase 3] A_base_v2 공정 비교 학습 및 보고서 산출물 생성
   └─ 동일 설정으로 A_base_v2 학습 완주
   └─ evaluate 2종 + compare 실행 -> reports/compare_A_v2/ 생성
   └─ C 드라이브 및 Git 동기화
```

## 5. 실행 옵션 선택지

- **옵션 A (권장 — 대책 ①+②+④ 일괄 적용)**:
  - 보상 재설계 + 커리큘럼 완화 + 시연 버퍼 30회 초기화 동시 적용.
  - SAC가 잡기(Grasp) 단계를 매우 빠르게 돌파하여 성공률 80% 이상을 안정적으로 달성할 수 있는 가장 확실한 경로.
- **옵션 B (대책 ①+② 우선 적용)**:
  - 시연 버퍼 없이 보상 재설계와 커리큘럼 완화만으로 `A_sym_v2`를 30만 스텝 먼저 시험.
  - 30만 스텝에서 `stage < 1`이면 그때 대책 ④(시연 버퍼)를 추가 투입.

## 6. 보고서(10점 만점 항목) 연계 전략

이 2차 튜닝 과정은 감점 요인이 아니라, 텀프로젝트 평가 기준에서 매우 높은 점수를 받을 수 있는 핵심 스토리라인입니다:
1. **문제 해결 및 분석 (4장, 10점)**:
   - 1차 실험에서 발생한 `grasp_fail`과 보상 수렴치(185점)의 불일치 원인을 정확히 규명(Hovering Hacking 및 속도 제한에 따른 연속 행동 탐색 붕괴).
   - 계획서 9장에 명시된 대책에 따라 보상 사다리 재설계 및 커리큘럼 조정을 거친 논리적 해결 과정 제시.
2. **비교실험 (5장, 10점)**:
   - 1차 비교(`reports/compare_A/`)와 2차 개선 비교(`reports/compare_A_v2/`)를 나란히 배치하여, 대칭 보상(`sym`)이 기본 모델(`base`) 대비 어떻게 탐색 효율과 최종 성공률을 높였는지 전후 비교로 입증.
