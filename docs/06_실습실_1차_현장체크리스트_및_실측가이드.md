# 실습실 1차(12/3~5) 현장 체크리스트 및 실측 가이드

> 12월 3~5일 분반 배정일에 실습실에서 수행하는 **카메라 보정, 큐브 색상 튜닝, 관측 오차 측정, 그리퍼 실측**에 대한 단계별 현장 절차서입니다.
> 담당: **역할 B (비전·DR 담당)** 및 **역할 C (로봇 제어 담당)**, 역할 A 동행

---

## 1. 사전 준비물 및 현장 네트워크 세팅

### 1.1 필수 준비물
- [ ] **노트북 및 전원 어댑터**: WSL 환경 (Git 최신 코드 `pull` 완료 상태)
- [ ] **줄자 또는 버니어 캘리퍼스**: 카메라 높이/직하점 및 그리퍼 간격 실측용 (필수)
- [ ] **조별 배정 색 큐브 (25 mm)**: 반사나 오염이 없는 깨끗한 상태
- [ ] **LAN 케이블 또는 공유기/핫스팟**: PC와 Jetson이 동일한 로컬 네트워크(동일 서브넷)에 접속

### 1.2 ROS 2 네트워크 일치화
모든 PC 및 Jetson 터미널에서 반드시 **조 번호**를 일치시켜야 합니다.
```bash

```

## 4. 실측 및 보정 4단계 (현장 필수 작업)

```text
[Step 1] 호모그래피 보정 (B)  ───> RMS < 2.0 mm 확보
       ↓
[Step 2] 색상(HSV) 튜닝 (B)  ───> real/config/real.yaml 반영
       ↓
[Step 3] 관측 오차 측정 (B)   ───> 9개 위치 x 2각도 = 18개 CSV 기록
       ↓
[Step 4] 그리퍼·관절 실측 (C) ───> 열림폭, 물림각도, 빈닫힘각도 기록
```

---

### Step 1. 호모그래피 보정 (역할 B)

체커보드 작업판을 카메라 좌표계에서 로봇 베이스(`base_link`) 좌표계로 변환하는 행렬을 계산합니다.

#### 1) 빈 작업판 사진 캡처
로봇과 큐브가 없는 깨끗한 작업판 상태에서 사진을 저장합니다.
```bash
python3 real/calibrate_homography.py --grab /tmp/topcam_empty.png
```

#### 2) 카메라 물리 높이 및 직하점(Nadir) 실측 (줄자 사용)
- **카메라 렌즈 높이 (`H_cam`)**: 작업판 표면부터 카메라 렌즈 중심까지의 수직 거리 (보통 약 `0.51` m).
- **카메라 직하점 (`Nadir`)**: 카메라 바로 수직 아래 지점의 로봇 기준 `(x, y)` 좌표 (줄자로 로봇 베이스 중심으로부터의 거리 측정, 보통 약 `0.29 0.04`).

#### 3) 꼭짓점 클릭 및 보정 행렬 생성
```bash
python3 real/calibrate_homography.py --image /tmp/topcam_empty.png \
        --camera-height 0.51 --camera-nadir 0.29 0.04 --out real/config/homography.yaml
```
- 화면 상단 안내에 따라 **체커 꼭짓점 11개**를 순서대로 클릭합니다 (#0번 빨간 점 기준).
- **목표 기준**: **RMS < 2.0 mm**, 최대 오차 < 4.0 mm
- 오차가 넘어가면 클릭을 다시 수행합니다.

#### 4) 보정 확인
```bash
python3 real/calibrate_homography.py --image /tmp/topcam_empty.png --check real/config/homography.yaml
```
- 노란색 격자와 빨간 목표 사각형(50×50 mm)이 실제 체커 눈금과 정확히 겹치는지 육안 확인합니다.

---

### Step 2. 색상(HSV) 튜닝 및 검출 확인 (역할 B)

조명 변화에 영향받지 않고 배정 색 큐브를 정확히 인식하도록 HSV 임계치를 맞춥니다.

#### 1) 큐브 사진 캡처
작업판 위에 배정된 색상의 큐브를 올려두고 캡처합니다.
```bash
python3 real/calibrate_homography.py --grab /tmp/topcam_cube.png
```

#### 2) 트랙바 튜닝 GUI 실행
```bash
python3 real/tune_hsv.py --image /tmp/topcam_cube.png
```
- 트랙바를 조정하여 큐브 영역만 깨끗하게 흰색 마스크로 잡히도록 범위를 설정합니다.
- 콘솔에 출력된 `low: [H, S, V]`, `high: [H, S, V]` 값을 복사합니다.

#### 3) `real/config/real.yaml` 파일에 반영
```yaml
detector:
  homography: real/config/homography.yaml
  hsv_ranges:
    - {low: [H_min, S_min, V_min], high: [H_max, S_max, V_max]}
```

#### 4) 검출 노드 실행 및 확인 (별도 터미널 2개)
```bash
# 터미널 A: 검출 노드 구동
python3 real/cube_detector.py --config real/config/real.yaml

# 터미널 B: 디버그 영상 및 토픽 확인
ros2 run rqt_image_view rqt_image_view /cube_debug
ros2 topic echo /cube_obs
```
- 영상에서 큐브 주위에 초록색 사각형과 중심점 좌표가 안정적으로 뜨는지 확인합니다.

---

### Step 3. 관측 오차 측정표 작성 (역할 B — 보고서 및 DR 핵심 근거)

시뮬레이션과 실물의 간극(Sim2Real Gap)을 측정하여 Domain Randomization(비교 B) 파라미터의 근거로 사용합니다.

#### 1) 측정 위치 (9곳 $\times$ yaw 2종 = 총 18개 측정)
체커 눈금을 기준으로 다음 9개 좌표에 큐브를 정밀하게 올려놓습니다:
- 중심 축: `(0.270, 0.000)`, `(0.330, 0.000)`, `(0.390, 0.000)`
- 좌우 오프셋:
  - `(0.270, +0.060)`, `(0.270, -0.060)`
  - `(0.330, +0.060)`, `(0.330, -0.060)`
  - `(0.390, +0.025)`, `(0.390, -0.025)`

#### 2) CSV 로깅 (위치마다 yaw 0°와 30°로 10초씩 기록)
```bash
mkdir -p logs/obs_eval
# 예: (0.270, 0.000) 위치에서 yaw 0도일 때
ros2 topic echo /cube_obs --csv > logs/obs_eval/obs_270_000_yaw0.csv
# 예: (0.270, 0.000) 위치에서 yaw 30도일 때
ros2 topic echo /cube_obs --csv > logs/obs_eval/obs_270_000_yaw30.csv
```

#### 3) 오차 분석 및 `task.yaml` 반영
- 각 CSV 파일에서 `참값 - 측정값`의 평균(편향, Bias)과 표준편차(잡음, Noise)를 산출합니다.
- 최대 편향을 `config/task.yaml > randomization.obs_pos_bias_m`에, 평균 표준편차를 `obs_pos_noise_m`에 반영합니다.

### Step 4. 그리퍼 및 관절 각도 실측 (역할 C)

시뮬레이션의 그리퍼 각도 및 검출 임계치가 실제 서보모터와 일치하는지 확인합니다.

#### 1) 로봇 토크 활성화
```bash
ros2 service call /robot/set_torque std_srvs/srv/SetBool "{data: true}"
```

#### 2) 그리퍼 개폐 각도 및 손가락 간격 실측
```bash
# (1) 열림 명령 (0.55 rad)
ros2 topic pub --once /joint_targets sensor_msgs/msg/JointState "{name: [gripper], position: [0.55]}"
ros2 topic echo /real/joint_states --once
```
- 자로 손가락 안쪽 간격을 측정하여 **약 50 mm** 내외인지 확인합니다.

```bash
# (2) 큐브를 손가락 사이에 끼우고 닫힘 명령 (-0.10 rad)
ros2 topic pub --once /joint_targets sensor_msgs/msg/JointState "{name: [gripper], position: [-0.10]}"
ros2 topic echo /real/joint_states --once
```
- 큐브에 막혀 멈춘 그리퍼 관절 각도(`q_grasp`)를 기록합니다 (예: `+0.05 ~ +0.12 rad`).

```bash
# (3) 큐브 없이 빈 상태로 닫힘 명령 (-0.10 rad)
ros2 topic pub --once /joint_targets sensor_msgs/msg/JointState "{name: [gripper], position: [-0.10]}"
ros2 topic echo /real/joint_states --once
```
- 손가락끼리 완전히 맞닿아 멈춘 각도(`q_empty`)를 기록합니다 (예: `-0.08 ~ -0.10 rad`).

#### 3) 실측 판정 조건
- 잡힘 판단 기준 `grasp_detect_rad`는 `q_empty < grasp_detect_rad < q_grasp` 사이의 값(보통 `0.00 rad`)이어야 합니다.
- 만약 실제 각도가 시뮬레이션 설정(`config/task.yaml > robot`)과 0.05 rad 이상 차이가 나면 `task.yaml`을 수정하고 A에게 알립니다.
