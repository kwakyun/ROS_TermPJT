# 원격 학습 결과 이관 및 실습실 배포 가이드

> 개인/외부 PC(WSL2)에서 강화학습을 수행한 후, 학습된 정책 모델과 평가 결과를 GitHub를 통해 실습실 환경으로 안전하게 이관하고 실물 로봇에 배포하는 전체 절차 안내 문서입니다.

---

## 1. 전체 흐름 요약

```text
[개인 PC (WSL)]                  [GitHub]                  [실습실 PC (WSL)]
2. 학습 완료 (policy_best.zip)
       ↓
3. 시뮬레이션 평가·비교 (reports/)
       ↓
WSL 홈 → Git 폴더 복사 ──── git push ────> git pull ────> 4. 실습실 1차: 보정·실측
                                                              ↓
                                                          6. 실습실 2차: 실물 로봇 배포
```

---

## 2. 학습 완료 직후 필수 작업 (시뮬레이션 평가 및 비교)

학습(1.5M 스텝)이 완료되면 즉시 실습실로 넘어가기 전, 현재 PC에서 **시뮬레이션 공식 평가와 비교 분석**을 먼저 수행해야 합니다. (텀프로젝트 보고서에 들어갈 필수 데이터와 그래프가 생성됩니다.)

### 2.1 평가 및 비교 명령어 실행 (WSL `~/termproject`)
```bash
# 가상환경 활성화 상태 확인
cd ~/termproject && source .venv/bin/activate && export PYTHONPATH=$PWD PYTHONDONTWRITEBYTECODE=1

# 1) 공식 Seed 0~9 + 추가 100회 시뮬레이션 평가
python -m pickplace.evaluate --run A_base_s7
python -m pickplace.evaluate --run A_sym_s7

# 2) 기준 모델(base)과 개선 모델(sym) 비교 보고서 생성
python -m pickplace.compare --runs A_base_s7 A_sym_s7 --labels base sym --tag nominal --out reports/compare_A
```

### 2.2 생성되는 산출물 확인
- `runs/<run>/eval_nominal/episodes_official.csv`: 보고서 '시뮬레이션 결과' 표에 사용할 Seed별 성공/종료 원인 기록.
- `reports/compare_A/`:
  - `success.png` (성공률 비교)
  - `yaw_bins.png` (초기 각도 구간별 성공률)
  - `margin.png` (목표 사각형 여유 공간 분포)
  - `learning_curve.png` (학습 곡선)
  - `table.md` (수치 요약표)

## 3. WSL 홈 $\rightarrow$ Git 저장소 이관 및 GitHub Push

학습은 속도 최적화를 위해 WSL 리눅스 내부 파일시스템(`~/termproject`)에서 수행되었으므로, Windows와 연동된 Git 저장소 폴더로 결과를 복사한 후 Push합니다.

### 3.1 결과 파일 복사
```bash
# WSL 터미널에서 C 드라이브 Git 작업 공간으로 runs 및 reports 복사
cp -r ~/termproject/runs /mnt/c/WorkSpace/ROS_TermPJT/termproject/
cp -r ~/termproject/reports /mnt/c/WorkSpace/ROS_TermPJT/termproject/
```

### 3.2 GitHub 업로드 대상 파일 및 용량 관리
정책 파일(`policy_best.zip`)은 **약 6MB**로 GitHub 단일 파일 제한(100MB) 이내이므로 정상 커밋/푸시가 가능합니다. 단, 수십 개의 중간 체크포인트와 대용량 텐서보드 파일은 저장소 용량을 불필요하게 키울 수 있으므로 핵심 파일 위주로 커밋합니다.

#### 필수 커밋 대상
- `runs/A_sym_s7/policy_best.zip` (검증 최고 성능 모델 — 실습실 배포용)
- `runs/A_sym_s7/policy_final.zip` (최종 스텝 모델)
- `runs/A_sym_s7/eval_history.csv` (학습 중 평가 이력)
- `runs/A_sym_s7/run_config.yaml` (실행 파라미터 메타데이터)
- `runs/A_base_s7/` 의 동일 핵심 파일들
- `reports/` 폴더 전체 (비교 그래프 및 통계표)

### 3.3 Git Commit & Push 실행
```bash
cd /mnt/c/WorkSpace/ROS_TermPJT

# 변경 및 산출물 추가
git add docs/
git add termproject/reports/
git add termproject/runs/A_sym_s7/policy_best.zip termproject/runs/A_sym_s7/policy_final.zip termproject/runs/A_sym_s7/eval_history.csv termproject/runs/A_sym_s7/run_config.yaml
git add termproject/runs/A_base_s7/policy_best.zip termproject/runs/A_base_s7/policy_final.zip termproject/runs/A_base_s7/eval_history.csv termproject/runs/A_base_s7/run_config.yaml

git commit -m "feat: add trained RL policies (A_sym_s7, A_base_s7) and simulation evaluation reports"
git push origin <본인브랜치명>
```

> **Tip (전체 백업)**: `runs/` 전체 폴더(TensorBoard 로그 및 모든 체크포인트 포함)는 USB 드라이브나 구글 드라이브에 별도로 압축하여 백업해 두는 것을 권장합니다.

## 4. 실습실 현장 적용 단계

실습실에 도착한 후, 실습실 PC에서 코드를 내려받고 실제 하드웨어와 연동합니다.

### 4.1 실습실 PC에서 코드 받기
```bash
cd ~/termproject  # 또는 실습실 프로젝트 경로
git pull origin <본인브랜치명>

# 모델 파일이 정상 위치에 있는지 확인
ls -lh runs/A_sym_s7/policy_best.zip
```

### 4.2 실습실 1차 (12/3~5 배정일) — 보정 및 실측 (역할 B·C)
실물 로봇에 정책을 바로 올리기 전에 환경 오차를 잡는 필수 단계입니다.
1. **호모그래피 보정**:
   ```bash
   python3 real/calibrate_homography.py --grab /tmp/topcam_empty.png
   python3 real/calibrate_homography.py --image /tmp/topcam_empty.png --camera-height 0.51 --camera-nadir 0.29 0.04 --out real/config/homography.yaml
   ```
2. **색상(HSV) 튜닝 & 검출 확인**:
   ```bash
   python3 real/tune_hsv.py --image /tmp/topcam_cube.png
   # 출력된 HSV 범위를 real/config/real.yaml 에 반영
   python3 real/cube_detector.py --config real/config/real.yaml
   ```
3. **관측 오차 및 그리퍼 실측**:
   - 큐브 배치 오차 및 손가락 개폐 실측치를 `config/task.yaml`에 반영.

### 4.3 실습실 2차 (12/10~12) — 실물 예비 시험 (실제 로봇 구동)
가져온 `policy_best.zip`을 실제 로봇에 연결하여 회차별 픽앤플레이스를 테스트합니다.

실습실 PC 터미널 구성:
- **터미널 1 (비전 검출)**:
  ```bash
  python3 real/cube_detector.py --config real/config/real.yaml
  ```
- **터미널 2 (정책 실행기 - 모델 로드)**:
  ```bash
  # 가져온 policy_best.zip을 자동으로 읽어 대기 상태 진입
  python3 real/policy_runner.py --config real/config/real.yaml --run A_sym_s7
  ```
- **터미널 3 (화면 모니터링)**:
  ```bash
  ros2 run rqt_image_view rqt_image_view /cube_debug
  ```
- **터미널 4 (로봇 동작 트리거)**:
  ```bash
  # 1. 토크 활성화
  ros2 service call /robot/set_torque std_srvs/srv/SetBool "{data: true}"

  # 2. 준비 자세 (그리퍼 열기)
  ros2 service call /pickplace/ready std_srvs/srv/Trigger

  # 3. 큐브 배치 후 픽앤플레이스 시작 (30초 후 자동 정지)
  ros2 service call /pickplace/start std_srvs/srv/Trigger

  # ※ 비상 정지 시
  ros2 service call /pickplace/stop std_srvs/srv/Trigger
  ```
