# 역할별 개념 정리 — 각자 숙지할 내용과 질의응답 대비

> 검사 때 학생마다 짧은 질문 1~2개로 **본인 담당 부분**과 **관측 → 정책 → 제어 전체 흐름**을 확인한다(TERM_PROJECT 2.4).
> 1장은 전원, 2~4장은 자기 역할 + 다른 역할 '한 줄 요약'까지 읽는다. 각 절 끝의 "직접 해 볼 것"을 실제로 실행해 두면 답이 자기 말로 나온다.

## 1. 전원 공통

### 1.1 전체 흐름을 30초로 설명하기
> "천장 카메라로 큐브 색을 찾아 체커 호모그래피로 base_link 좌표와 yaw를 얻고, 관절각에서 FK로 그리퍼 위치를 계산해 28(또는 30)차원 관측을 만듭니다. SAC 정책이 20 Hz로 말단 이동량·손목 회전·그리퍼 개폐 5개를 내면, IK가 4개 관절 목표로 바꾸고 arm_io가 속도 제한을 걸어 서보에 보냅니다. 시뮬레이션과 실물은 입력 출처만 다르고 관측 생성·추론·IK 코드는 같습니다."

### 1.2 과제 조건 (외워 둘 숫자)
| 항목 | 값 |
|---|---|
| 큐브 | 25 mm, 11 g (시뮬), 배정 색 |
| 시작 | 중심 X 0.270~0.330, Y −0.060~0.060, yaw −180~180°, 빈 그리퍼 준비 자세, 비접촉 |
| 목표 | (0.390, 0.000) 중심 50×50 mm, **밑면 전체**가 안에, 해제 후 **2초 유지** |
| 시간 | 30초 (시뮬은 물리 시간: 0.05 s × 600 스텝) |
| 빨간 점 | (0.270, 0.000), 체커 한 칸 60 mm, 빨간 점에서 위로 두 칸 꼭짓점 = 목표 중심 |
| 점수 | 시뮬 10(8회↑ 만점), 실물 30(4회 중 상위 3회), 설계 20, 비교 10, 분석 10, 개인 20 |

### 1.3 강화학습 기본 용어 (이 과제 기준으로)
- **MDP**: 상태(로봇·큐브), 행동(5차원), 보상(단계형), 전이(MuJoCo 물리 25 스텝 = 0.05 s), 할인율 γ=0.98.
- **에피소드 종료**: terminated(성공·영역 밖) vs truncated(30초). truncated는 "실패가 아니라 시간이 끊긴 것"이라 가치 추정에서 다르게 다룬다.
- **정책 π(a|s)**: 관측을 넣으면 행동 분포를 내는 신경망(256-256-256 MLP). 평가·실물에서는 `deterministic=True`로 평균 행동만 사용.
- **SAC**: off-policy actor-critic. 리플레이 버퍼의 과거 경험을 재사용(표본 효율↑), Q 함수 2개 중 작은 값으로 과대평가 억제, 엔트로피 보너스(α 자동 조정)로 탐험 유지. 연속 행동에 적합.
- **PPO와 차이**: PPO는 on-policy(최근 데이터만 사용, 안정적이지만 데이터를 많이 씀), 병렬 환경이 많을 때 유리. 우리는 CPU·환경 수가 적어 SAC를 택함.
- **커리큘럼**: 학습 초반에는 시작 범위·yaw를 30%로 좁혔다가 학습 50% 시점까지 100%로 넓힘. 기본·개선 모두 같게 적용 → 비교 공정성 유지.

### 1.4 RL과 IK의 경계 (질문 단골)
- IK는 "제어점을 (x, y, z)로 옮기려면 관절을 몇 도로" 만 계산하는 **변환기**다.
- 언제 접근하고, 얼마나 손목을 돌리고, 언제 닫고·들고·옮기고·내리고·여는지는 **전부 정책 출력**이다. 스크립트 상태기계(`tools/scripted_check.py`)는 환경 검증 전용이고 제출 정책에 쓰지 않는다.

### 1.5 비교실험 두 개를 한 문장씩
- **A**: 큐브는 90°마다 같은 모양인데 (sin θ, cos θ)는 θ와 θ+90°를 다른 상황으로 보이게 한다 → (sin 4θ, cos 4θ)와 ±45°로 접은 정렬 오차를 주면 같은 상황이 같은 입력이 되어 학습이 쉬워지고, 목표 축에 맞춰 놓으면 위치 허용 오차가 ±7.3 mm(45° 틀어짐)에서 ±12.5 mm(정렬)로 커진다.
- **B**: 시뮬은 실물보다 깨끗하므로 마찰·질량·서보 강성·속도·관측 편향·잡음·지연·가림을 무작위로 섞어 학습하면 실물 오차에 덜 민감한 정책이 된다.

### 1.6 예상 공통 질문
| 질문 | 답의 핵심 |
|---|---|
| 밀기만 해서 넣으면 왜 실패인가요? 코드에서 어떻게 막았나요? | 과제 조건. `SuccessTracker`가 '들기' 단계를 거쳐야 다음으로 진행, 운반 보상은 들린 상태에서만, 잡지 않은 채 큐브를 움직이면 패널티 |

## 2. 역할 A — 시뮬레이션·RL

### 2.1 Gymnasium 환경 구조 (`pickplace/env.py`)
- `reset(seed)`: RNG 고정 → 큐브 X·Y·yaw 균등 추출 → 준비 자세 → 접촉 검사 → 20 스텝 정착(시간 0으로 되돌림). Seed가 같으면 배치가 같다 → Seed 0~9 재현성.
- `step(a)`: Action → `ActionMapper`(IK) → 정책 목표 → **속도 제한 램프**(`cmd += clip(target−cmd, ±vmax·dt)`, 실물 arm_io 흉내) → `mj_step` 25회 → 접촉·꼭짓점 계산 → `SuccessTracker.update` → 보상 → 관측.
- `info`: `end_reason`(success / grasp_fail / lift_fail / timeout_carrying / timeout_not_released / outside_goal / dropped / out_of_area), `max_stage`, `sim_time`, `start_xy/yaw`.

### 2.2 보상 설계 원리 (`pickplace/reward.py`)
- **보상 해킹**: 정책은 점수가 오르는 어떤 방법이든 찾는다. 예) 거리 보상만 주면 큐브를 밀어 목표에 넣음, 잡기 보상을 매 스텝 더하면 잡고 버팀.
- **단계형 최댓값**: 단계 보상을 더하지 않고 max → 다음 단계로 가야만 보상이 오름. 값 순서 reach 0.25 < grasp 0.35 < lift 0.5 < carry 0.8 < place 1.0 < release 1.3(+0.5).
- **조건부 지급**: carry는 들린 상태, release는 "해제 + 목표 안 + 한 번 들었음". 이 조건 하나하나가 과제 성공 조건과 대응한다.
- **희소 보너스**: 성공 +50 (종료 시 1회). γ=0.98이면 약 50스텝(2.5 s) 앞의 행동까지 신호가 전달됨.
- 보상 항은 `info["reward_terms"]`에 남으므로 학습이 막히면 어떤 항이 지배하는지 본다.

### 2.3 관측 정규화·대칭 (`pickplace/observation.py`, `geometry.py`)
- 각도는 원시값 대신 sin·cos로 (−π/π 불연속 제거). 그리퍼는 180° 대칭이라 2φ, 큐브는 90° 대칭이라 4θ.
- `fold_quarter(a)`: (a+45°) mod 90° − 45°. `align_error(θ, φ)`: 손목을 몇 도 돌리면 닫힘 축이 큐브 면에 수직이 되는지(최대 ±45°).
- 큐브 위치는 '추정값'(카메라가 높이를 모름, 잡으면 가려짐) → 시뮬 관측도 실물과 같은 제약을 갖게 설계.

### 2.4 SAC 하이퍼파라미터 의미 (`config/task.yaml > training`)
| 값 | 의미 | 조정 감각 |
|---|---|---|
| `learning_rate 3e-4` | 신경망 갱신 크기 | 불안정하면 1e-4 |
| `buffer_size 1e6` | 경험 저장량 | 학습 스텝 이상 |
| `batch_size 512` | 한 번 갱신에 쓰는 표본 | |
| `gamma 0.98` | 미래 보상 할인 | 에피소드가 길면(최대 600) 0.98~0.99 |
| `tau 0.005` | 타깃 Q 네트워크 이동 평균 | |
| `ent_coef auto` | 탐험(엔트로피) 자동 조정 | 너무 빨리 결정적이 되면 고정값 0.1 |
| `learning_starts 1e4` | 이 스텝까지는 무작위 행동으로 버퍼만 채움 | |
| `n_envs 4` | 병렬 환경 수 | CPU 코어 수만큼 |

### 2.5 실험·평가 방법
- **공정 비교**: 바꾸는 변수 하나(관측/보상 변형)만 다르게, 나머지(스텝·seed·커리큘럼·평가 seed) 동일.
- **학습 seed와 평가 seed 구분**: 학습 seed는 신경망 초기화·탐험, 평가 seed는 큐브 배치. 학습 seed를 2개 이상 쓰면 "운"과 "방법 차이"를 구분할 수 있다.
- **지표**: 성공률 + yaw 구간별 성공률 + 놓은 위치 여유(mm) + 종료 원인 분포 + 학습 곡선. 성공률만 보면 '왜'를 설명 못 한다.
- 검증 seed(50000~)는 공식 seed(0~9)와 겹치지 않게 → 공식 평가에 과적합 방지.

### 2.6 직접 해 볼 것
1. `python -m tools.scripted_check --seeds 0 1 2` 출력의 `events`로 단계 전이 시간을 읽어 본다.
2. `reward.py`에서 `stage = max(...)`를 `sum(...)`으로 바꿔 짧게 학습하면 무엇이 달라질지 예측해 본다(실제 제출 코드는 되돌림).
3. `runs/<run>/eval_history.csv`와 `monitor/*.csv`의 `max_stage` 분포로 학습이 어느 단계에서 막히는지 판단해 본다.

|---|---|
| 왜 단계 보상을 더하지 않고 최댓값을 썼나요? | 합산하면 앞 단계에 머무르며 보상을 쌓는 해킹이 가능. 최댓값이면 다음 단계로 가야만 증가 |

## 3. 역할 B — 실물 관측·Domain Randomization (비교 B)

### 3.1 카메라 모델과 호모그래피 (`real/vision.py`, `calibrate_homography.py`)
- 핀홀 카메라: 3D 점이 이미지 평면에 투영. **평면 위 점**끼리는 3×3 행렬 H 하나로 픽셀 ↔ 평면 좌표 변환이 된다(호모그래피, 8자유도 → 4점 이상 필요).
- 대응점: 체커 꼭짓점은 x = 0.270 + 0.060·i, y = 0.060·j 로 좌표를 정확히 안다. 빨간 점(0.270, 0)이 기준. 11점을 클릭해 `cv2.findHomography`(최소자승) → 점별 재투영 오차(mm)로 품질 확인.
- 렌즈 왜곡이 크면 가장자리 오차가 커진다 → 대응점을 작업 영역(X 0.15~0.45, Y ±0.12) 주변에 고르게.

### 3.2 시차(parallax) 보정
- H는 '작업판 평면'용인데 카메라는 높이 h=25 mm인 큐브 윗면을 본다 → 카메라 바로 아래점(nadir)에서 멀수록 바깥쪽으로 밀려 보인다.
- 닮은 삼각형: 실제 = nadir + (H로 구한 점 − nadir) × (1 − h / 카메라 높이). 카메라 높이 약 0.51 m면 축소율 약 5 %, 중심에서 15 cm 떨어진 큐브는 약 7 mm 보정.
- 시뮬 카메라 시험: 보정 전 평균 3.0 mm → 보정 후 1.7 mm (`tools/check_vision_sim.py`).

### 3.3 색 분할과 yaw 추정
- BGR → HSV(색상 H, 채도 S, 명도 V): 조명 밝기 변화에 H가 덜 민감. 빨강은 H가 0과 180에 걸쳐 범위 2개 필요.
- 모폴로지 열기(작은 점 제거)·닫기(구멍 메움) → 가장 큰 윤곽 → `minAreaRect`(최소 회전 사각형) → 4꼭짓점을 H로 변환 → 변 방향으로 yaw → ±45°로 접음(정사각형이라 원래 그 이상 구분 불가).
- 오검출 방지: 면적 범위, ROI, 프레임 사이 3 cm 이상 튀면 버림, 위치는 지수 평활(α=0.6). yaw는 ±45° 경계에서 값이 뒤집히므로 평활하지 않음.

### 3.4 가림·지연·검출 실패 처리 (`observation.CubeEstimator`)
- 잡는 순간 '큐브 − 제어점' 오프셋을 고정 → 잡혀 있는 동안은 제어점 + 오프셋으로 위치를, 그리퍼 yaw 변화로 큐브 yaw를 추정.
- 검출이 0.25 s 이상 끊기면 마지막 값 유지. 시뮬에서도 DR로 같은 상황(검출 실패 5%, 가림 반경 2 cm, 지연 0~2 스텝)을 만든다.

### 3.5 Domain Randomization 설계 원칙 (`config/task.yaml > randomization`)
| 항목 | 범위 | 근거(측정으로 갱신) |
|---|---|---|
| 큐브 마찰 | ×0.7~1.3 | 실물 큐브 재질·손가락 패드 상태 차이 |
| 큐브 질량 | ×0.8~1.2 | 3D 프린트 충진율 차이 |
| 서보 강성(kp) | ×0.8~1.2 | 실물 위치 추종 지연 |
| 관절 속도 | ×0.85~1.15 | arm_io 램프·부하 |
| 관측 편향 | ±3 mm, ±0.05 rad (회차 고정) | **호모그래피 재투영 오차 측정값으로 정함** |
| 관측 잡음 | σ 2 mm, 0.03 rad (매 스텝) | 정지 큐브 검출값의 표준편차 측정 |
| 지연 | 0~2 스텝 | 카메라 → 검출 → 토픽 지연 측정 |
| 검출 실패·가림 | 5 %, 반경 2 cm | 검출률 측정 |
- 원칙: **측정한 실물 오차를 덮을 만큼 넓게, 학습이 무너지지 않을 만큼 좁게**. 너무 넓으면 보수적인 정책이 되어 공칭 성능이 떨어짐 → 그래서 노이즈 시험 환경과 공칭 환경 둘 다 평가한다.
- 노이즈 시험 환경(`eval_noise.yaml`)은 학습 범위보다 약간 넓다 → "처음 보는 오차"에 대한 강건성.

## 4. 역할 C — 실물 제어·통합

### 4.1 기구학 (`pickplace/kinematics.py`)
- 로봇: 5축 + 그리퍼(SO-101 계열, STS3215). 관절: shoulder_pan, shoulder_lift, elbow_flex, wrist_flex, wrist_roll, gripper.
- `gripperframe` site 정의(실측): **+X 접근 축**, **+Z 닫힘 축**(고정 손가락→움직이는 손가락), 원점 = 고정 손가락 끝.
- 제어점 = site + 18 mm(+Z) − 5 mm(+X): 큐브 중심을 이 점에 맞추면 고정 손가락과 5.5 mm 여유 → 닫으면 큐브가 고정 손가락 쪽으로 밀리며 잡힘.
- **FK**: 관절각 → site 위치·자세 (MuJoCo `mj_kinematics`).
- **IK(감쇠 최소자승, DLS)**: 오차 e = [위치 오차; w·자세 오차], Δq = Jᵀ(JJᵀ + λ²I)⁻¹e 를 반복. λ(0.02)는 특이점 근처에서 관절이 폭주하지 않게 함. w(0.015)가 작아 위치가 우선 → 멀리서는 자세를 자동으로 기울임.
- 측정 결과: x ≤ 0.30 m 수직 가능, 0.33 m 약 6~10°, 목표 0.39 m 약 28°, 0.415 m 약 38° 기울어짐. elbow −1.29 rad 근처가 팔을 다 편 한계.

### 4.2 제어 루프와 속도 제한
- 정책 20 Hz → `/joint_targets` → arm_io(30 Hz 제어 타이머)가 `max_vel_rad_s`로 램프 → 서보.
- 시뮬도 같은 램프(`env.cmd`)를 쓰므로 정책은 "명령하면 바로 가지 않는다"는 실물 특성을 학습 중에 이미 겪는다.
- 0.35 rad/s × 0.05 s = 스텝당 0.0175 rad → 팔 끝 약 4 mm. 스크립트 기준 전체 과제 약 10~11 s (30 s 상한 대비 여유).

### 4.3 ROS 2 통합 (`real/policy_runner.py`)
| 토픽/서비스 | 방향 | 형식 |
|---|---|---|
| `/real/joint_states` | Jetson arm_io → PC | JointState (6관절, 20 Hz) |
| `/top_cam` | Jetson → PC | Image bgr8 640×480 |
| `/cube_obs` | cube_detector → runner | Float64MultiArray [x, y, yaw, valid, stamp] |
| `/joint_targets` | runner → arm_io | JointState (이름+위치) |
| `/robot/set_torque` | 서비스 | SetBool |
| `/pickplace/ready, start, stop` | 서비스 | Trigger |
- 같은 `ROS_DOMAIN_ID`, PC·Jetson 같은 네트워크(4주차). venv에서 rclpy를 쓰려면 `source /opt/ros/humble/setup.bash` 후 venv 활성화(9주차와 동일).

### 4.4 안전 설계
- 관절 상태가 0.3 s 이상 끊기면 정지(현재 자세 유지), 측정값에서 0.35 rad 이상 먼 목표는 잘라서 전송, 관절 한계 클램프(arm_io도 한계 밖 명령 거부), 준비 자세가 아니면 start 거부, 30 s 자동 종료.
- 작업면 아래 목표 금지(제어점 z ≥ 4 mm), IK 실패 요청은 팔 정지.
- 토크는 arm_io 시작 시 꺼져 있음 → 토크 ON은 사람이 확인 후 서비스로.

### 4.5 그리퍼 실측 (실습실 1차 필수)
| 측정 | 시뮬 값 | 실물 측정 | 반영 위치 |
|---|---|---|---|
| 열림 각(간격 ≈ 50 mm) | 0.55 rad | | `robot.gripper_open_rad` |
| 큐브 잡았을 때 멈춘 각 | ≈ 0.14~0.18 rad | | `robot.grasp_detect_rad`(이 값과 빈 닫힘 사이) |
| 빈 채로 닫았을 때 각 | ≈ −0.10 rad | | `robot.gripper_closed_rad` |
| 관절 속도 한계 | joints.yaml 값 | | `robot.max_joint_vel_rad_s` |
값을 바꾸면 **A에게 알려 재학습**(관측 정의가 바뀌므로).
