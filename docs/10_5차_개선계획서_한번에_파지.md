## 2. 근본 원인

### 원인 ① — 그리퍼 각도 기준값이 "큐브를 잡은 각도" 범위 안에 있음

시뮬레이션에서 큐브를 들고 있는 동안의 그리퍼 관절각을 측정함.

| 상태 | 그리퍼 각도 [rad] |
|---|---|
| 큐브를 잡고 들어 올린 상태 | **−0.02 ~ 0.14** (5~95%), 평균 0.03~0.06 |
| 빈 그리퍼 완전 닫힘 | 약 −0.10 |

문제가 되는 기준값:

| 위치 | 현재 코드 | 문제 |
|---|---|---|
| `pickplace/train.py` `markov_demo_action` | `gripped = ... (0.01 < gq < 0.20)` | 꽉 쥐어 각도가 0.01 아래로 내려가면 "안 잡음"으로 판단 → **공중에서 열기 명령** |
| `config/task.yaml` `robot.grasp_detect_rad` | `0.00` | 관측의 "잡힘" 플래그가 잡고 있는 동안에도 켜졌다 꺼졌다 함 (시뮬레이션·실물 `PolicyCore` 공통) |

### 원인 ② — 들기 분기와 운반 분기 사이의 무한 진동

- 들기 목표 높이 0.062 m, 분기 경계 0.052 m(관측 기준 약 0.056 m)
- 경계를 넘어 운반 분기로 가면 앞으로 이동하는 IK 해가 **wrist_flex 한계(1.658 rad)**에 걸려 높이가 0.0557 m로 떨어짐 → 다시 들기 분기 → 반복
- 결과: 꽉 쥔 채 제자리에서 수 초~수십 초 흔들림 → `timeout_carrying` 또는 미끄러짐 낙하
- 확인 로그 (seed 1003, t = 5.05 s): 목표 wrist_flex 1.635, 측정 1.638 / 다음 스텝 목표 1.658(한계)

### 원인 ③ — 보상이 "한 번에"를 따로 장려하지 않음 (미검증 가설)

- `SuccessTracker`는 낙하 시 단계를 `approach`로 되돌릴 뿐 감점이 없음
- 다시 잡아서 성공해도 `success_bonus=100`을 그대로 받으므로, RL이 낙하를 피할 이유가 약함

|---|---|---|---|---|

**마르코프 원칙과의 관계**: `_EXPERT["carry"]`는 관측에 없는 숨은 상태임. 숨은 상태 없이 같은 효과를 내려는 버전(바닥 근처에서만 수직 들기)도 시험했으나, 목표에서 해제하지 못하고 멈춰 성공 24%에 그침. 실제 궤적에서는 들어 올린 뒤 팔이 항상 운반 높이에 머물러 "들기 중" 상태와 "운반 중" 상태가 관측상 겹치지 않으므로, BC 학습에서 생기는 행동 충돌은 작을 것으로 판단함. 보고서에 이 판단 근거를 적음.

### 3.3 항목 4 — 그리퍼 잠금 (안전 필터)

`ActionMapper.__call__`의 그리퍼 명령 부분에 적용. 시뮬레이션과 실물이 같은 코드를 쓰므로 sim2real 일관성이 유지됨.

```python
# 관측 가능한 값(FK 제어점, 관절각)만 사용
holding = closed_cmd_prev and q_meas[GRIPPER_INDEX] > grasp_detect_rad
if holding and gp[2] > rest_z + 0.008:
    self.latched = True                          # 들어 올린 뒤부터 잠금
if self.latched:
    near_goal = np.linalg.norm(gp[:2] - goal_xy) < 0.015 and gp[2] < rest_z + 0.012
    if not near_goal:
        q_t[GRIPPER_INDEX] = self.g_closed      # 목표 위·낮은 높이가 아니면 열기 금지
    if not holding or near_goal:
        self.latched = False
```

- **반드시 학습 단계부터 넣어야 함.** 현재 정책에 잠금만 씌워 시험했더니 성공률이 61% → 7%로 떨어짐(70회). 다시 잡기를 학습한 정책이 강제로 닫힌 그리퍼 때문에 학습 분포 밖으로 벗어남.
- `near_goal`의 높이 조건(12 mm)은 너무 엄격하면 `timeout_not_released`가 늘어남 → 재학습 결과를 보고 조정
- 보고서에서 "언제 놓을지는 정책이 결정하고, 안전 계층은 허용 구역 밖에서 여는 것만 막음"으로 설명 → RL 사용 확인과 충돌하지 않음

## 부록 — 진단에 쓴 방법

- `A_sym_v4/policy_best.zip`의 가중치(`policy.pth`)를 numpy MLP(tanh, 256-256)로 직접 실행
  - 진단 환경에서 `PPO.load`가 충돌해서 이 방법을 씀
  - 저장 시 정규화가 첫 층에 병합돼 있어 원 관측을 그대로 입력함
- 낙하 분류 기준: 낙하 직전 8스텝(0.4 s) 안에 그리퍼 열기 명령이 있었는지, 한쪽 손가락 접촉이 먼저 끊겼는지, 큐브 기울기가 15°를 넘었는지
- 사용 시드: 공식 0~9, 추가 1000~1089 (평가 시드와 같은 범위, 시연 수집 시드 20000+와 겹치지 않음)
