## 3. 1일차 (12/3~5) — 보정 · 실측 · 초기 시운전

```text
[1] 호모그래피 보정 (RMS < 2 mm) → [2] HSV 색상 튜닝 & /cube_obs 확인
    → [3] 4종 실물 오차·그리퍼 실측 → [4] A_sym_v8 시운전 & 재학습 여부 판단
```

### Step 1. 카메라 물리 실측 및 호모그래피 보정
1. **빈 작업판 캡처** (작업판 위에 로봇 팔과 큐브가 치워진 상태):
   ```bash
   python3 real/calibrate_homography.py --grab /tmp/topcam_empty.png
   ```
2. **줄자로 2가지 실측**:
   - `--camera-height`: 작업판 표면 ~ 카메라 렌즈 중심 수직 높이 `[m]` (시뮬 참고값 `0.5139 m`)
   - `--camera-nadir`: 카메라 바로 수직 아래 지점의 `base_link` `(x, y)` 좌표 `[m]` (시뮬 참고값 `0.29084 0.03815`)
3. **체커 꼭짓점 11개 클릭 보정**:
   ```bash
   python3 real/calibrate_homography.py --image /tmp/topcam_empty.png \
           --camera-height <실측높이_m> --camera-nadir <x_m> <y_m> \
           --out real/config/homography.yaml
   ```
   - `#0`은 빨간 인쇄 기준점 `(0.270, 0.000)`입니다. 창 상단에 표시되는 순서대로 클릭합니다 (`u`: 되돌리기, `s`: 계산·저장, `q`: 종료).
   - **목표 기준**: **`rms_error_mm < 2.0 mm`**, **`max_error_mm < 4.0 mm`**.
4. **격자 재투영 육안 검증**:
   ```bash
   python3 real/calibrate_homography.py --image /tmp/topcam_empty.png --check real/config/homography.yaml
   ```
   - 노란 체커 격자와 **빨간 50×50 mm 목표 정사각형**이 실제 인쇄 선과 정확히 겹치는지 확인합니다.

### Step 2. 배정 큐브 색상(HSV) 튜닝 및 검출 노드 확인
1. **큐브 올린 영상 저장 & 트랙바 튜닝**:
   ```bash
   python3 real/calibrate_homography.py --grab /tmp/topcam_cube.png
   python3 real/tune_hsv.py --image /tmp/topcam_cube.png
   ```
   - 트랙바(`H lo/hi`, `S lo/hi`, `V lo/hi`)를 움직여 오른쪽 마스크에서 **큐브만 깨끗한 흰색**으로 남게 맞춘 뒤 `q`를 누릅니다.
   - 콘솔에 출력된 `- {low: [...], high: [...]}` 줄을 복사해 `real/config/real.yaml`의 `detector.hsv_ranges`에 덮어씁니다. (빨강처럼 색상환 양끝에 걸치면 2개 구간 입력)
2. **검출 노드 실행 및 실시간 확인** (터미널 2개):
   ```bash
   # [T1] 검출 노드
   python3 real/cube_detector.py --config real/config/real.yaml
   # [T2] 디버그 영상 & 토픽
   ros2 run rqt_image_view rqt_image_view /cube_debug
   ros2 topic echo /cube_obs
   ```
   - 큐브를 여러 각도·위치에 놓아도 초록 윤곽선과 중심·yaw가 튀지 않고 유지되는지 확인합니다. (깜빡이면 `detector.min_area_px`/`max_area_px` 또는 `roi_px` 조정)

### Step 3. 현장 4대 핵심 실측 (Sim2Real Gap 계량화)
실측값은 `logs/`에 기록해 비교 B 및 보고서(§4.4) 근거로 사용합니다.

1. **카메라 관측 오차(Bias & Noise) — 9개 위치 × 2개 yaw = 18회 CSV 기록**:
   - 체커 눈금 기준 9곳: `(0.270, 0.000)`, `(0.330, 0.000)`, `(0.390, 0.000)`, `(0.270, ±0.060)`, `(0.330, ±0.060)`, `(0.390, ±0.025)`
   - 각 위치에 `yaw = 0°`, `30°`로 놓고 약 10초씩 `/cube_obs` 저장:
     ```bash
     mkdir -p logs/obs_eval
     ros2 topic echo /cube_obs --csv > logs/obs_eval/obs_270_000_yaw0.csv
     ```
   - `참값 - 측정값` 평균의 최대값(편향, `obs_pos_bias_m`)과 표준편차(`obs_pos_noise_m`), 각도 오차(`obs_yaw_bias_rad`, `obs_yaw_noise_rad`)를 산출합니다.
2. **카메라 프레임 지연·주기 & 로봇 팔 가림(Occlusion) 확인**:
   - `ros2 topic hz /top_cam`과 `ros2 topic hz /cube_obs` 측정 (20 Hz 정책 주기 대비 프레임 지연 스텝 추정).
   - 로봇 팔을 큐브 위 접근 경로(`ready_tcp_xyz` → 파지 위치)에 두었을 때 `/cube_debug`에서 큐브가 가려지는 시점과 지속 시간을 확인합니다.
     - *(참고: 시뮬 Vision-in-the-Loop `seed=2`에서 접근 초기 가림으로 `det=5/600`이 발생하며 `cube_timeout_s=0.25` 만료로 실패한 사례가 있으므로, 실물에서 가림이 길면 `real.yaml`의 `cube_timeout_s` 여유 또는 조명/각도 점검 필요)*
3. **그리퍼 개폐 각도·간격 및 파지 임계치 실측**:
   ```bash
   ros2 service call /robot/set_torque std_srvs/srv/SetBool "{data: true}"
   # (1) 열림 (0.55 rad): 자로 손가락 안쪽 간격 ≈ 50 mm 확인
   ros2 topic pub --once /joint_targets sensor_msgs/msg/JointState "{name: [gripper], position: [0.55]}"
   ros2 topic echo /real/joint_states --once
   # (2) 25 mm 큐브를 끼운 상태로 닫힘 (-0.10 rad): 멈춘 각도 q_grasp 기록 (시뮬 -0.02~0.14)
   ros2 topic pub --once /joint_targets sensor_msgs/msg/JointState "{name: [gripper], position: [-0.10]}"
   ros2 topic echo /real/joint_states --once
   # (3) 빈 상태로 닫힘 (-0.10 rad): 멈춘 각도 q_empty 기록 (시뮬 -0.08~-0.10)
   ros2 topic pub --once /joint_targets sensor_msgs/msg/JointState "{name: [gripper], position: [-0.10]}"
   ros2 topic echo /real/joint_states --once
   ```
   - **판정 확인**: `q_empty < grasp_detect_rad (-0.05) < q_grasp` 조건이 여유 있게 성립해야 합니다. 차이가 `0.05 rad` 이상이면 `config/task.yaml > robot`을 실측값으로 수정합니다.
4. **작업판 마찰 및 `A_sym_v8` 1~2회 안전 시운전**:
   - 큐브를 중앙 쉬운 위치 `(0.300, 0.000, 0°)`에 두고 §4.1 절차대로 `A_sym_v8`을 1~2회만 시험 구동합니다.
   - 확인 포인트: ① 파지 시 큐브가 손가락에 밀려 나가지 않는지, ② 운반 중 작업판 바닥에 닿거나 스치지 않는지, ③ 목표 `(0.390, 0.000)`에서 해제 후 드리프트가 없는지.

### Step 4. 1일차 종료 후 의사결정 (재학습 여부)
- **Case A (차이 작음)**: 호모그래피 RMS < 2 mm, 위치 편향 ≤ 3 mm, `q_empty < -0.05 < q_grasp` 성립, `A_sym_v8` 시운전 안정 → **기존 `A_sym_v8`·`B_dr_v8` 유지**, 2일차에 바로 정식 비교 시험.
- **Case B (실측 괴리 확인됨)**: `grasp_detect_rad`가 0.05 rad 이상 다르거나, 실측 `obs_pos_bias_m`/`obs_delay_steps`/`cube_friction_scale`이 기존 설정을 벗어남 →
  1. 실측값을 `config/task.yaml` (`robot`, `randomization`)에 반영
  2. `python -m tools.scripted_check` (10/10 확인) & `python -m tools.check_runner_parity` (`PARITY OK`) 재검증
  3. 필요 시 `B_dr_real` 재학습(또는 `A_sym_v8` 기반 맞춤 DR 미세조정) 후 2일차 전까지 WSL 평가 완료
- **1일차 마무리 Git 반영**:
  ```bash
  git add real/config/homography.yaml real/config/real.yaml logs/obs_eval/
  git commit -m "Lab day 1: calibration, HSV tuning, and real-world measurements"
  git push origin main
  ```

모든 터미널은 §2.2(`ros2` source → `.venv` → `PYTHONPATH`, `ROS_DOMAIN_ID`) 완료 상태에서 실행합니다.

| 터미널 | 역할 | 실행 명령 |
|---|---|---|
| **T1 (비전)** | 큐브 검출 발행 | `python3 real/cube_detector.py --config real/config/real.yaml` |
| **T2 (정책)** | 20 Hz 정책 추론·제어 | `python3 real/policy_runner.py --config real/config/real.yaml --run A_sym_v8` *(비교 시 `--run B_dr_v8`)* |

### 4.2 회차별 실행 루틴 (T4)
```bash
# 최초 1회 토크 ON
ros2 service call /robot/set_torque std_srvs/srv/SetBool "{data: true}"

# --- 매 회차 반복 ---
# 1) 준비 자세 이동 (그리퍼 열림, 2~3초 정지 대기)
ros2 service call /pickplace/ready std_srvs/srv/Trigger

# 2) 다른 팀원이 무작위 (X 0.270~0.330, Y ±0.060, yaw ±π)에 큐브 배치 후 좌표·각도 메모

# 3) 회차 시작 (30 s 자동 타이머 + logs/real/ CSV 자동 저장, 이후 손대지 않음)
ros2 service call /pickplace/start std_srvs/srv/Trigger

# (충돌·폭주 위험 시에만 즉시 정지)
ros2 service call /pickplace/stop std_srvs/srv/Trigger
```

### 4.3 정책 선정 시험 & CSV 실패 원인 분석
1. **비교 시험**: `A_sym_v8` 4~5회, `B_dr_v8`(또는 실측 보정 `B_dr_real`) 4~5회를 동일 난이도 배치(다양한 `yaw`, 가장자리 `Y=±0.05` 포함)로 수행하고 §7 표에 점수를 기록합니다.
2. **실패 로그 디버깅 (`logs/real/<YYYYmmdd_HHMMSS>_trialN.csv`)**:
   - `cube_visible`: 0으로 오래 끊기면 비전 가림·조명·`cube_timeout_s` 점검
   - `grasped_est`: 큐브를 잡았는데 `0`이면 `grasp_detect_rad` 불일치, 빈손인데 `1`이면 그리퍼 각도/오프셋 점검
   - `ik_error`: 12 mm(`max_accepted_ik_error_m`) 근접/초과 시 목표 영역 외곽 도달 한계
   - `a_dx, a_dy, a_dz, a_dyaw, a_grip` & `tgt_*`: 목표 근처에서 `a_grip`이 열리지 않으면(`timeout_not_released`형) 배치 여유(`est_margin`) 오차 점검

- 2일차 비교에서 **상위 3회 합산 점수·안정성이 가장 높은 run** 1개를 최종 정책으로 확정합니다.

### 5.2 본 평가 직전 10분 점검 순서
1. **카메라·작업판 물리 고정 확인**: 전날 대비 카메라 거치대 흔들림 없는지 확인
2. **호모그래피 `--check`**: `calibrate_homography.py --grab /tmp/check.png` → `--check real/config/homography.yaml`로 노란 격자·빨간 목표 사각형 일치 확인
3. **HSV 검출 확인**: `cube_detector.py` + `rqt_image_view /cube_debug`로 작업판 중앙·모서리 3곳 인식 및 `yaw` 떨림 확인
4. **로봇 기동 확인**: `arm_io` → `/robot/set_torque true` → `/pickplace/ready`로 부드러운 자세 이동 확인 후 4회 본 평가 진행

### 5.3 이상 상황 즉시 중단 기준
- 서보가 작업판에 과도하게 눌려 끼익거림, 케이블 걸림, 예기치 않은 급가속 발생 시 즉시 **`/pickplace/stop`** 호출 (필요 시 `set_torque false` 또는 비상 전원 차단).

## 6. 현장 증상별 즉시 트러블슈팅

| 증상 | 주요 원인 | 현장 즉시 조치 |
|---|---|---|
| `/top_cam`·`/real/joint_states` 안 보임 | `ROS_DOMAIN_ID` 불일치, PC–Jetson 망 분리 | 양쪽 `echo $ROS_DOMAIN_ID`, 같은 공유기·방화벽(`ufw`) 확인 |
| `ModuleNotFoundError: rclpy` | `.venv` 활성화 후 ROS `setup.bash` 실행 | 새 터미널에서 **ROS `setup.bash` → `.venv` 순서**로 재실행 |
| `/pickplace/start` 거부 (`not at ready pose`) | 관절이 `q_ready` 대비 `> 0.08 rad` 오차 | `/robot/set_torque true` 확인 후 `/pickplace/ready` 호출하고 2~3초 정지 대기 |
| 접근 도중 팔이 멈칫하거나 헛손질 (`seed=2`형) | 로봇 팔이 `/top_cam` 시야 가림 + `cube_timeout_s=0.25` 만료 | 조명 균일화, `min_area_px` 미세 하향, 필요 시 `cube_timeout_s` 조정 점검 |
| `/cube_debug` 초록 박스가 깜빡임·각도 튐 | 실습실 반사광·그림자 변화 | 큐브 놓인 상태에서 `tune_hsv.py` 재조정, `roi_px`로 작업판 외곽 배제 |
| 잡기 위치가 항상 한쪽으로 `5+ mm` 밀림 | 카메라 높이(`--camera-height`)·직하점(`--camera-nadir`) 오차 | 줄자로 높이·직하점 재측정 후 `calibrate_homography.py` 재보정 |
| 큐브를 잡았는데 `grasped_est=0` | 실물 `q_grasp`가 `grasp_detect_rad(-0.05)`보다 작거나 반대 | §3 Step 3-3으로 `q_empty`, `q_grasp` 재측정 후 `task.yaml` 갱신·재학습 |
| 목표 경계에 살짝 걸려 안 놓음 (`seed=6`형) | 목표 근처 호모그래피 편향으로 `est_margin < 0` 인식 | `(0.390, 0.000)` 부근 호모그래피 재투영 오차 및 시차 높이(`0.025`) 점검 |
