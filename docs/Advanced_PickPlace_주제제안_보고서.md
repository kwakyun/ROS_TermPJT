# 임베디드 시스템 텀프로젝트 — Advanced 단일 큐브 Pick-and-place 주제 제안 보고서

> 작성일: 2026-11-11 · 대상 Task: **Advanced (×1.00)** — 무작위 시작 배치에서 집기·들어 올리기·운반·내려놓기
> 목적: 11/23~25 계획서 제출 전에 "무엇을 개선 주제로 삼아 비교실험할지"와 전체 설계 방향을 정함

---

## 0. 한 줄 결론

**추천 주제: "큐브의 90° 회전 대칭성을 반영한 관측·행동 설계로 무작위 yaw Pick-and-place의 성공률과 실물 강건성 높이기"**

- **필수 비교실험 (기본 vs 개선)**: 큐브 yaw를 그대로 넣은 관측(기본) vs 90° 대칭을 반영한 yaw 인코딩 + 정렬 보상(개선)
- **여유가 있으면 추가할 비교**: Domain Randomization(DR) 미적용 vs 적용 — sim2real 대응 근거로 사용
- 이유: Advanced의 핵심 난관이 **yaw [-π, π] 무작위**와 **밑면 전체가 50 mm 정사각형 안**이라는 두 조건인데, 둘 다 "큐브 방향을 어떻게 다루느냐"로 연결됨. 학습 2회만으로 차이가 뚜렷하게 나올 가능성이 높아 비교실험 10점·설계 20점 근거로 쓰기 좋음.

## 1. 과제 조건 정리 (설계에 직접 영향을 주는 것만)

| 항목 | 조건 | 설계상 의미 |
|---|---|---|
| 큐브 | 한 변 25 mm, 조별 배정 색 | 색 기반 검출 가능 → 실물 관측을 카메라 색 분할로 구현 |
| 시작 배치 | 중심 X [0.270, 0.330], Y [-0.060, 0.060], **yaw [-π, π]** | 위치·방향 모두 관측해야 함. 미리 잡기·접촉 금지 |
| 목표 영역 | 중심 (0.390, 0.000), **50 × 50 mm 정사각형**, 밑면 전체가 들어가야 함 | 놓는 순간 큐브 yaw에 따라 허용 오차가 달라짐 (아래 1.1) |
| 성공 조건 | 집기 → 밑면이 작업면에서 떨어짐 → 운반 → 놓기 → **그리퍼 완전 해제** → **2초 유지** | 밀기·잡은 채 맞추기는 실패. 해제와 후퇴까지 정책이 해야 함 |
| 시간 | 30초 (시뮬레이션도 물리 시간 30초) | 제어 주기 10~20 Hz면 300~600 step 상한 |
| 시뮬레이션 평가 | Seed 0~9, 10회, 8회 이상 성공 시 10점 | 시드 고정 재현성이 중요 |
| 실물 평가 | 4회 중 상위 3회, 회차당 10점(완성도 5 / 안정성 3 / 관측·제어 대응 2) | **실물이 30점으로 비중이 가장 큼** → sim2real 설계가 중요 |
| RL | 모든 Task에서 RL 필수, "정책 로딩 → 추론 → 로봇 명령" 연결을 확인함 | 스크립트 상태머신이 과제를 다 하면 안 됨 |

### 1.1 목표 영역 허용 오차는 큐브 yaw에 따라 달라짐

큐브 반변 12.5 mm, 목표 반변 25 mm. 큐브가 목표 축에 대해 θ만큼 돌아가 있으면 X 방향 반폭은 `12.5 × (|cos θ| + |sin θ|)` mm임.

| 놓을 때 yaw (목표 축 기준) | 큐브 반폭 | 중심 허용 오차 (각 축) |
|---|---|---|
| 0° (축 정렬) | 12.5 mm | **±12.5 mm** |
| 22.5° | 16.3 mm | ±8.7 mm |
| 45° | 17.7 mm | **±7.3 mm** |

→ **축에 맞춰 놓으면 허용 오차가 약 1.7배 커짐.** 실물의 카메라 오차·그리퍼 미끄러짐을 생각하면 이 차이가 성공률을 크게 좌우함. 이 관찰이 추천 주제의 출발점임.

### 1.2 큐브는 90°마다 같은 모양임

큐브를 위에서 잡을 때 yaw가 θ든 θ+90°든 잡는 방법은 같음. 그런데 yaw를 원시값 θ 또는 (sin θ, cos θ)로 넣으면 정책은 θ와 θ+90°를 다른 상황으로 배우고, ±π 경계에서는 값이 끊김. 이 때문에 학습이 느려지고 특정 yaw 구간에서 손목을 크게 돌리다 실패하는 경향이 생김.

## 2. 주제 후보 비교

| 후보 | 기본 방법 → 개선 방법 | 장점 | 약점 | 추천도 |
|---|---|---|---|---|
| **A. yaw 대칭성 반영 관측** | 원시 yaw → `(sin 4θ, cos 4θ)` + 잡기 yaw 오차를 [-45°, 45°]로 접어서 입력, 놓기 정렬 보상 | 구현 간단, 학습 2회로 비교 가능, 무작위 yaw 성공률에 직접 효과, 1.1의 허용 오차 논리로 근거 설명이 명확 | 단독으로는 실물 강건성 근거가 약함 | ★★★★★ |
| **B. Domain Randomization** | 고정 물리·관측 → 마찰·질량·관측 노이즈·지연·큐브 위치 오차 무작위화 | 실물 30점과 직결, "실물 대응" 5점 근거 | 시뮬레이션 성공률이 오히려 떨어질 수 있음, 효과 확인에 실물 시간이 필요 | ★★★★ (A와 함께) |
| C. 단계형 보상 + 커리큘럼 | 단일 거리 보상 → 접근·잡기·들기·운반·놓기·해제 단계형 보상, 쉬운 시작 배치부터 넓혀 가기 | Pick-and-place 학습 자체를 성공시키는 데 거의 필수 | 사실상 "기본"도 이걸 써야 학습이 됨 → 비교 대상으로는 약함 | ★★★ (기본 설계에 포함) |
| D. Action 공간 | 관절 각도 delta → 말단(EE) 직교 좌표 delta + 손목 yaw (IK 사용) | 학습 효율·실물 안정성 향상 | IK 구현 부담, 비교 위해 관절 공간 버전도 따로 학습해야 함 | ★★★ |
| E. 알고리즘 비교 | PPO vs SAC | 보고서에 쓰기 쉬움 | 과제 특성과 연결된 설계 근거가 약함, 평가표가 "Task에 맞는 선택 근거"를 봄 | ★★ |
| F. Residual RL | 스크립트 IK 궤적 + RL 보정 | 실물 성공률 높음 | 스크립트 비중이 크면 "RL 사용" 확인에서 불리할 수 있음 | ★★ |

**결정**: A를 주 비교 주제로 정하고, C·D는 공통 기본 설계로 깔고, B는 3주차 여유에 따라 두 번째 비교로 추가함. 평가표에 "개선 요소 한 가지를 비교해도 충분함"이라고 되어 있으므로 A 하나만으로도 비교실험 점수는 받을 수 있음.

## 3. 추천 시스템 설계

### 3.1 전체 흐름

```
[천장 카메라] → 색 분할 → 큐브 픽셀 중심·방향 → 체커 호모그래피 → base_link XY, yaw
        ↓
[관측 벡터] (+ 로봇 관절 상태, 그리퍼 상태)
        ↓
[RL 정책 (PPO 또는 SAC)] 10~20 Hz
        ↓
[Action] EE Δx, Δy, Δz, Δyaw, 그리퍼 열림/닫힘
        ↓
[IK + 관절 한계·속도 제한] → 로봇 관절 명령
```

- 로봇은 탑뷰 그림상 5축 + 그리퍼 소형 암으로 보임(정확한 모델명은 수업 자료로 확인 필요). 손목 회전축이 있으면 **위에서 내려 잡는 자세(top-down)로 고정하고 손목 yaw만 바꾸는 방식**이 가장 단순하고 안정적임.
- IK는 저수준 제어기일 뿐이고 언제 접근·하강·잡기·들기·운반·놓기·해제할지는 **정책이 결정**해야 함. 이 경계를 보고서에 명시하면 "RL 사용" 확인에 유리함.

### 3.2 관측 (Observation)

| 구성 | 기본 방법 | 개선 방법 (주제 A) |
|---|---|---|
| 큐브 위치 | 큐브 중심 xyz (base_link) | 동일 |
| 큐브 방향 | `(sin θ, cos θ)` 또는 원시 θ | **`(sin 4θ, cos 4θ)`** — 90° 주기 연속 인코딩 |
| 잡기 정렬 오차 | 없음 | **`wrap_45(θ_cube − θ_gripper)`** — [-45°, 45°]로 접은 값 |
| 상대 위치 | EE − 큐브, 큐브 − 목표 | 동일 |
| 로봇 상태 | 관절 각도·속도, EE 위치, 그리퍼 개폐 | 동일 |
| 잡힘 상태 | 그리퍼 폭(닫혔는데 완전히 닫히지 않음 = 큐브를 잡음) | 동일 |
| 시간 | 남은 시간 비율 | 동일 |

실물 대응 포인트: 잡는 동안 그리퍼가 큐브를 가려 카메라 검출이 끊길 수 있음 → **검출 실패 시 마지막 값 유지 + 그리퍼 폭 기반 잡힘 상태로 보완**. 시뮬레이션에서도 같은 가림·지연을 흉내 내 학습시키면 "관측 및 제어 대응" 2점 근거가 됨.

### 3.3 행동 (Action)

- `[Δx, Δy, Δz, Δyaw, g]`, 각 성분 [-1, 1] → 스텝당 최대 이동 예: 1 cm, 10°
- `g > 0`이면 닫기, 아니면 열기 (연속값을 이진화하거나 속도 명령으로 사용)
- 작업면 아래로 내려가지 않게 z 하한, 작업 영역 밖으로 나가지 않게 xy 범위 제한
- 실물 진동 방지: 스텝당 이동량 제한 + 저역통과 필터 → "동작 안정성" 3점 근거

### 3.4 보상 (Reward) — 단계형

| 단계 | 보상 | 비고 |
|---|---|---|
| 접근 | `−‖EE − 큐브 위 잡기점‖` + 손목 정렬 보상 `cos(4·(θ_cube−θ_gripper))` | 개선 방법에서만 정렬 항 사용 |
| 잡기 | 두 손가락 접촉 + 그리퍼가 큐브 폭으로 닫힘 시 보너스 | |
| 들기 | 잡힌 상태에서 큐브 높이 보상 (목표 3~5 cm까지) | **잡힌 상태에서만** 지급 |
| 운반 | `−‖큐브 xy − 목표 xy‖` | **들린 상태에서만** 지급 → 밀기 전략 학습 방지 |
| 놓기 | 목표 위에서 하강, 목표 축 정렬 보상 `cos(4·θ_cube)` | 1.1의 허용 오차 확대 효과 |
| 해제·유지 | 그리퍼 열림 + EE 후퇴 + 밑면 전체가 영역 안 + 2초 유지 시 큰 성공 보너스 | 성공 판정은 큐브 네 꼭짓점이 모두 영역 안인지로 계산 |
| 패널티 | 행동 크기, 관절 한계 근접, 큐브 낙하·영역 이탈, 잡지 않은 상태에서 큐브 이동(밀기), 시간 | |

- 종료 조건: 성공(2초 유지 완료), 큐브가 작업판 밖으로 떨어짐, 30초 초과
- 학습 초기에는 시작 배치 범위를 좁게 시작해 넓히는 **커리큘럼**을 적용 (기본·개선 모두 같은 커리큘럼 사용 → 비교 공정성 유지)

### 3.5 실물 적용 (sim2real)

| 문제 | 대응 |
|---|---|
| 큐브 위치를 base_link 좌표로 바꾸기 | 천장 카메라 + 작업판 체커 꼭짓점과 빨간 기준점 (0.270, 0.000)으로 **호모그래피 보정** |
| 큐브 yaw 추정 | 색 마스크 → `minAreaRect` 각도 → 90° 주기라 그대로 `4θ` 인코딩에 사용 가능 (방향 모호성 자체가 사라짐 — 주제 A의 실물 이점) |
| 관측 노이즈·지연 | 시뮬레이션에서 위치 ±3~5 mm, yaw ±5°, 1~3 스텝 지연을 무작위로 주어 학습 (주제 B) |
| 마찰·그리퍼 힘 차이 | 마찰계수·큐브 질량 무작위화, 잡은 뒤 들 때 속도 제한 |
| 서보 응답 차이 | 행동 스케일 제한, 관절 속도 제한, 제어 주기 고정 |

## 4. 비교실험 계획

### 4.1 필수: 주제 A (yaw 대칭 관측)

| | 기본 | 개선 |
|---|---|---|
| 관측 | `(sin θ, cos θ)` | `(sin 4θ, cos 4θ)` + `wrap_45` 정렬 오차 |
| 보상 | 단계형 (정렬 항 없음) | 단계형 + 잡기·놓기 정렬 항 |
| 그 외 | 알고리즘·하이퍼파라미터·학습 스텝·커리큘럼·학습 시드 모두 동일 | |

측정 지표 (같은 평가 시드에서):

1. **성공률** — Seed 0~9 공식 평가 + 추가 100회 무작위 평가
2. **yaw 구간별 성공률** — [-π, π]를 8구간으로 나눠 막대그래프 (기본은 특정 구간, 특히 ±π 근처에서 떨어질 것으로 예상)
3. **놓은 위치 여유** — 최종 꼭짓점과 영역 경계 사이 최소 거리 (mm)
4. **학습 곡선** — 같은 스텝에서 성공률이 얼마나 빨리 오르는지
5. **평균 수행 시간**, 실패 원인 분류 (잡기 실패 / 운반 중 낙하 / 영역 밖 / 시간 초과)

### 4.2 선택: 주제 B (Domain Randomization)

- 개선 A 설정 위에서 DR 미적용 vs 적용
- 평가 조건: **노이즈를 넣은 시뮬레이션 테스트 환경**(관측 노이즈·지연·마찰 변화)에서 두 정책 비교 + 15주차 실물 예비 시험 각 4~5회
- 기대: 공칭 환경 성공률은 비슷하거나 약간 낮아도, 노이즈 환경과 실물에서 차이가 커야 함. 성능이 좋아지지 않아도 원인 해석이 타당하면 점수를 받을 수 있음

## 7. 위험 요소와 대비

| 위험 | 대비 |
|---|---|
| 정책이 밀기만 학습함 | 운반 보상을 "들린 상태"에서만 지급, 잡지 않은 상태에서 큐브 이동 시 패널티 |

| 검사 당일 변수 | 12/17~19 이후 정책·파라미터 고정, 카메라 보정 절차를 체크리스트로 정리 |

## 8. 계획서(1페이지)용 요약 문안

> **Task**: Advanced — 단일 큐브 Pick-and-place (×1.00)
> **주제**: 큐브의 90° 회전 대칭성을 반영한 관측·보상 설계로 무작위 yaw 조건의 집기·놓기 성공률과 실물 강건성 향상
> **시작 조건 구현**: MuJoCo에서 시드별로 큐브 중심 X [0.270, 0.330], Y [-0.060, 0.060], yaw [-π, π] 무작위 배치, 빈 그리퍼 준비 자세에서 시작, 물리 시간 30초 상한
> **성공 조건 구현**: 잡힘(양 손가락 접촉) → 밑면 높이 > 0 → 그리퍼 완전 해제 → 큐브 네 꼭짓점이 (0.390, 0.000) 중심 50 mm 정사각형 안 → 2초 유지를 단계별로 판정
> **방법**: EE 직교 좌표 delta + 손목 yaw + 그리퍼 행동, 단계형 보상, PPO(또는 SAC). 실물은 천장 카메라 색 검출 + 체커 호모그래피로 base_link 좌표 관측
> **비교실험**: 원시 yaw 관측(기본) vs 90° 대칭 인코딩 + 정렬 보상(개선), 여유 시 DR 미적용 vs 적용
> **일정·역할**: 5장·6장 표 요약

## 9. 바로 확인할 것

1. 수업용 로봇의 정확한 모델, 손목 회전축 유무, 그리퍼 최대 개폐 폭 (25 mm 큐브를 여유 있게 잡을 수 있는지)
2. 제공 MuJoCo 모델에 그리퍼 접촉 센서·카메라가 포함되어 있는지
3. 실습실에서 천장 카메라 설치가 가능한지 (불가하면 손목 카메라 또는 고정 측면 카메라로 대체 설계 필요)
4. 제공 코드에 IK 또는 EE 제어 인터페이스가 있는지 (없으면 D안 대신 관절 delta Action으로 시작)
