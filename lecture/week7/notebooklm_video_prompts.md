# NotebookLM 7주차 짧은 영상 프롬프트 모음

## 사용 방법

1. NotebookLM에 `week7_summary_quiz.md`를 소스로 추가한다.
2. 아래 프롬프트 중 하나만 복사해 영상 생성 지시에 붙여 넣는다.
3. 다음 영상을 만들 때는 다른 프롬프트를 하나씩 사용한다.

각 영상은 1~2분 길이로 요청했다. 조교님 구두 질문에 대비할 수 있도록 영상 끝에 확인 질문과 짧은 답을 넣게 했다.

## 1. 7주차 전체 흐름과 YOLO Pose

```text
제공된 7주차 요약 자료만 근거로 한국어 1~2분짜리 교육용 짧은 영상을 만들어 주세요. 주제는 "카메라 영상에서 ROS Topic까지: 7주차 전체 흐름"입니다.

먼저 컴퓨터 비전의 출력 네 가지(Classification, Detection, Segmentation, Keypoint)를 한 장면씩 짧게 비교하고, 이번 실습의 YOLO Pose는 Detection의 Box에 Keypoint 하나를 더한 것이라고 설명해 주세요. 이번 Pose는 영상의 2D 점이지 로봇의 XYZ나 Roll/Pitch/Yaw가 아니라는 점을 강조해 주세요.

다음으로 네 단계를 흐름도 애니메이션으로 보여 주세요. yolo_dataset_tool.py로 촬영·라벨링하고 train/val로 나누기 → yolo_finetune.py로 yolo11n-pose.pt를 Jetson GPU에서 파인튜닝해 vision_pose_best.pt 만들기 → yolo_pose_live.py로 ROS 없이 확인하기 → Launch로 top_camera_publisher의 /top_cam을 yolo_object_detector가 받아 /vision/<클래스>/pixel, detected, confidence, bbox 발행하기.

마지막에 "큐브와 tip은 각각 어떤 점을 출력하나요?"라고 묻고, "큐브는 검출 Box 중심, tip은 예측 Keypoint이며 둘 다 640×480 픽셀 좌표"라고 답해 주세요. 화면 글자는 짧고 읽기 쉽게 구성해 주세요.
```

## 2. 지도학습, 학습과 추론, 파인튜닝

```text
제공된 7주차 요약 자료만 근거로 한국어 1~2분짜리 설명 영상을 만들어 주세요. 주제는 "이번 실습은 왜 지도학습인가"입니다.

지도학습(입력+정답), 비지도학습(정답 없이 군집화), 강화학습(행동 후 보상)을 세 칸 비교 화면으로 보여 주세요. 비지도 군집 번호가 자동으로 cube1·cube2라는 의미를 갖지 않는다는 점도 짧게 언급해 주세요.

학습 반복 과정을 "예측 → 정답과 비교해 오차 계산 → 가중치 갱신"의 순환 화살표로 보여 주고, 정답 tip (335, 247)과 예측 tip (320, 220)의 차이를 예시로 써 주세요. 이어서 학습(이미지+정답으로 가중치 수정, 결과는 모델 파일)과 추론(새 이미지만 입력, 고정된 가중치로 결과 출력)을 표로 비교해 주세요. 사전학습 yolo11n-pose.pt를 시작점으로 우리 큐브 색과 tip 기준을 추가 학습하는 것이 파인튜닝이며, 시작 파일과 결과 파일 vision_pose_best.pt를 혼동하지 말라고 정리해 주세요.

마지막에 "추론 때 정답을 넣지 않으니 비지도학습 아닌가요?"라고 묻고, "학습 방식은 학습 단계에서 쓴 신호로 구분하며, 사람이 만든 정답으로 학습했으므로 지도학습"이라고 답해 주세요.
```

## 3. 클래스 정의와 좋은 라벨링

```text
제공된 7주차 요약 자료만 근거로 한국어 1~2분짜리 교육 영상을 만들어 주세요. 주제는 "모델이 배울 정답 기준 만들기: cube1, cube2, tip"입니다.

vision.yaml의 세 클래스를 표로 보여 주세요. ID 0 cube1과 1 cube2는 point_mode box_center로 큐브 전체 Box만 그리면 중심점이 자동으로 정해지고, ID 2 tip은 manual로 도구 주변 Box를 그린 뒤 기준점을 직접 클릭합니다. 클래스 ID는 목록 순서이고, 한 이미지에서 클래스당 객체 하나, 객체당 Keypoint 하나라는 점을 짚어 주세요. 큐브 색과 tip 기준은 촬영 전에 description에 기록해야 합니다.

좋은 라벨과 나쁜 라벨을 좌우 비교 그림으로 보여 주세요. 큐브 전체를 감싼 Box와 일부 면만 감싸 중심이 치우친 Box를 비교하고, 매번 같은 물리적 점을 클릭한 경우와 그리퍼 중앙과 날 끝을 섞어 클릭한 경우를 비교하고, 위치를 모르는 점에서 N을 누른 경우와 추측해서 클릭한 경우를 비교해 주세요. 라벨링 순서(Space로 고정 → cube1 Box → cube2 Box → tip Box → tip 점 → 저장)도 짧게 보여 주세요.

마지막에 "tip Box의 중심을 tip으로 쓰면 안 되나요?"라고 묻고, "Box 중심과 팀이 정한 도구 끝점은 일치하지 않으므로 같은 물리적 점을 직접 클릭해 Keypoint로 학습시킨다"고 답해 주세요.
```

## 4. 영상 좌표와 라벨 파일 형식

```text
제공된 7주차 요약 자료만 근거로 한국어 1~2분짜리 설명 영상을 만들어 주세요. 주제는 "픽셀 좌표와 YOLO Pose 라벨 한 줄 읽기"입니다.

1920×1080 원본이 640×480으로 늘려져(stretch) 저장되고, 라벨과 추론이 같은 변환을 쓴다는 점을 그림으로 보여 주세요. 미리보기의 검정 여백은 저장되지 않습니다. 좌표계는 왼쪽 위가 (0, 0)이고 u는 오른쪽, v는 아래로 증가하며, 원본 중앙 (960, 540)이 저장 영상의 (320, 240)에 대응한다는 것을 애니메이션으로 보여 주세요. 출력 좌표는 m 단위 로봇 좌표가 아니라는 점도 강조해 주세요.

이어서 라벨 한 줄의 8개 값 class_id, cx, cy, w, h, kx, ky, visibility를 칸마다 색으로 구분해 보여 주세요. 좌표는 0~1로 정규화하고, visibility는 2가 위치 지정, 0이 위치 미상이며, 위치 미상이면 마지막 세 값이 0 0 0입니다. 객체가 없으면 그 줄을 빼고, 모두 없으면 빈 라벨 파일이 된다는 것도 설명해 주세요.

마지막에 "출력 좌표 (320, 240)은 무엇을 의미하나요?"라고 묻고, "640×480 영상 기준 화면 중앙의 픽셀 좌표이며 로봇 위치가 아니다"라고 답해 주세요.
```

## 5. 데이터 다양성, 검증, Confidence

```text
제공된 7주차 요약 자료만 근거로 한국어 1~2분짜리 교육 영상을 만들어 주세요. 주제는 "많이 찍는 것보다 다양하게 찍기: 검증과 결과 판단"입니다.

같은 장면을 반복 촬영한 사진과 위치·방향·그리퍼 상태·조명·배경·부분 가림·빈 작업판을 바꾼 사진을 대비해 보여 주세요. Train은 가중치 학습, Validation은 성능 확인과 best 모델 선택에 쓰며 약 80:20으로 나눈다고 설명해 주세요. 비슷한 연속 사진이 양쪽에 섞이면 검증 결과가 실제보다 좋아 보이므로, 학습에 쓰지 않은 새 장면으로 따로 검사해야 합니다. 과적합은 학습 장면에만 잘 맞는 현상이지만, 라벨 오류나 기준 불일치일 수도 있으니 단정하지 말라고 덧붙여 주세요.

새 장면 검사 다섯 가지(중앙, 가장자리, 부분 가림, 조명 변화, 빈 작업판)를 체크리스트로 보여 주고, Box가 맞아도 tip이 다른 부위를 가리키면 실패라고 강조해 주세요. Confidence는 모델의 예측 점수일 뿐 정확도 백분율이 아니고, NMS는 중복 Box를 정리한다는 점을 짧게 설명해 주세요.

마지막에 "검출이 잘 안 되면 임계값을 낮추면 되나요?"라고 묻고, "틀린 결과까지 통과할 수 있으므로 라벨 기준과 데이터 다양성을 먼저 확인하고 실패한 조건의 이미지를 보완한다"고 답해 주세요.
```

먼저 학습 기본 설정을 카드 형태로 보여 주세요. 다음으로 extract_detections의 선택 규칙을 단계별 필터 애니메이션으로 보여 주세요. 클래스별 후보를 신뢰도 높은 순으로 검사 → Box confidence 0.35 미만 제외 → 큐브는 Box 중심을 점으로 사용 → tip은 Keypoint confidence도 0.35 이상이어야 함 → 점이 640×480 밖이면 제외 → 처음 통과한 후보 하나를 채택.

마지막에 "왜 .vision.json이 필요한가요?"라고 묻고, "수집·학습·추론이 같은 클래스와 점 기준, 영상 크기를 쓰는지 검사하기 위해서"라고 답해 주세요.

## 7. ROS 2 노드, Topic, 미검출 처리

```text
제공된 7주차 요약 자료만 근거로 한국어 1~2분짜리 교육 영상을 만들어 주세요. 주제는 "검출 결과를 ROS 2 Topic으로 받기"입니다.

top_camera_publisher가 20 Hz로 640×480 bgr8 영상을 /top_cam에 Sensor Data QoS로 발행하고, yolo_object_detector가 콜백에서 추론해 클래스마다 pixel(PointStamped), detected(Bool), confidence(Float32), bbox(Float32MultiArray)와 /vision/debug_image를 발행하는 구조를 그림으로 보여 주세요. Launch는 Camera를 Node로, Detector는 Ultralytics가 설치된 가상환경 python3로 실행하려고 ExecuteProcess로 실행한다는 점도 설명해 주세요. pixel의 z=0은 깊이 측정값이 아닙니다.

검출됐을 때와 안 됐을 때를 좌우로 비교해 주세요. 미검출이면 detected=false, confidence=0을 발행하고 pixel과 bbox는 새로 발행하지 않으므로, 마지막 pixel을 현재 위치로 쓰면 안 됩니다. 카메라 입력 자체가 끊기면 false도 오지 않으므로 제어에서는 detected와 메시지 시각을 함께 검사해야 한다는 점을 강조해 주세요. 확인 명령 ros2 topic echo /vision/tip/detected와 /vision/cube1/pixel을 화면에 짧게 띄워 주세요.

마지막에 "카메라가 끊기면 detected=false가 오나요?"라고 묻고, "영상 콜백이 실행되지 않아 오지 않을 수 있으므로 메시지 시각도 함께 확인한다"고 답해 주세요.
```
