# NotebookLM 6주차 짧은 영상 프롬프트 모음

## 사용 방법

1. NotebookLM에 `week6_summary_quiz.md`를 소스로 추가한다.
2. 아래 프롬프트 중 하나만 복사해 영상 생성 지시에 붙여 넣는다.
3. 다음 영상을 만들 때는 다른 프롬프트를 하나씩 사용한다.

각 영상은 1~2분 길이로 요청했다. 조교님 구두 질문에 답하는 데 도움이 되도록, 설명 끝에 핵심 확인 질문과 짧은 답을 넣도록 했다.

---

## 1. 전체 제어 파이프라인 한눈에 보기

```text
제공된 6주차 요약 자료만 근거로 한국어 1~2분짜리 교육용 짧은 영상을 만들어 주세요. 주제는 “게임패드에서 실제 로봇 팔까지: 6주차 전체 흐름”입니다.

처음에는 다음 흐름을 간단한 애니메이션으로 보여 주세요: 게임패드 → joy_node의 /joy → joystick_to_pose의 /target_pose와 /gripper_open → ik_solver의 /joint_targets → arm_driver와 서보 → /joint_states → fk_solver의 /ee_pose. /safety/torque_enable이 arm_driver로 들어가는 것도 별도 화살표로 표시해 주세요.

각 노드가 맡은 일을 한 문장씩 설명하고, 영상 마지막에는 “목표 자세를 관절 명령으로 바꾸는 노드는?”, “실제 관절 상태로 현재 손끝 자세를 계산하는 노드는?”을 질문한 뒤 각각 ik_solver, fk_solver라고 답해 주세요. 목표와 측정 결과를 혼동하지 않도록 해 주세요. 전문 용어는 처음에만 풀어 설명하고, 화면 글자는 짧고 읽기 쉽게 구성해 주세요.
```

## 2. 작업 공간과 관절 공간, FK와 IK

```text
제공된 6주차 요약 자료만 근거로 한국어 1~2분짜리 설명 영상을 만들어 주세요. 주제는 “손끝을 움직이는 명령과 관절각의 관계: Task Space, Joint Space, FK, IK”입니다.

로봇 팔 그림을 사용해 Task Space는 EEF의 X, Y, Z, Pitch로 목표를 표현하고, Joint Space는 shoulder_pan, shoulder_lift, elbow_flex, wrist_flex, wrist_roll의 각도로 표현한다는 점을 비교해 주세요. FK는 관절각에서 EEF 위치와 방향을 계산하고, IK는 목표 EEF 자세에서 관절각을 찾는 역방향 계산이라는 점을 양방향 화살표로 보여 주세요.

마지막에 “FK와 IK의 입력·출력을 각각 말해 보세요”라고 물은 뒤 짧은 모범 답변을 제시해 주세요. 그리퍼는 arm 5개 관절의 IK에 포함되지 않고 별도 명령이라는 점도 한 문장으로 덧붙여 주세요.
```

## 3. 조이스틱 입력이 목표 자세가 되는 과정

```text
제공된 6주차 요약 자료만 근거로 한국어 1~2분짜리 교육 영상을 만들어 주세요. 주제는 “/joy 입력을 EEF 목표로 바꾸기”입니다.

joystick_to_pose가 /joy의 axes와 buttons를 저장하고 25 Hz Timer로 목표를 갱신하는 과정을 설명해 주세요. 현재 코드의 매핑 axes[1]→X, axes[0]→Y, axes[7]→Z, axes[3]→Pitch, buttons[0]→그리퍼 토글을 화면에 인덱스와 함께 표시해 주세요. 버튼 표기는 게임패드 모델마다 다를 수 있으므로 A/B 이름을 단정하지 말고, 실제 배열은 /joy를 확인해야 한다고 강조해 주세요.

입력값에 속도와 dt를 곱해 목표를 누적하고 Deadzone 및 작업 공간 제한을 적용한다는 내용을 쉬운 그림으로 보여 주세요. 마지막에는 “스틱을 놓으면 왜 입력 타임아웃이 아닐 수 있나요?”라고 묻고, 중립 /joy 메시지가 계속 들어올 수 있기 때문이라고 답해 주세요.
```

## 4. IK Solver는 어떻게 관절 해를 찾나

```text
제공된 6주차 요약 자료만 근거로 한국어 1~2분짜리 설명 영상을 만들어 주세요. 주제는 “숫자로 EEF 목표를 따라가는 IK Solver”입니다.

목표 X-Y 방향에서 shoulder_pan을 구하고, 이전 해 또는 측정 관절 상태를 초기값으로 사용하는 과정을 소개해 주세요. shoulder_lift와 elbow_flex를 조금씩 바꾸어 3×2 수치 Jacobian을 근사하고, Damped Least Squares로 위치 오차를 줄이는 방향을 계산한다는 점을 직관적인 화살표 애니메이션으로 보여 주세요. 최대 8회 반복, 관절 변화 제한, wrist_flex = target_pitch - shoulder - elbow 관계도 화면에 간단히 표시해 주세요.

위치 오차가 0.020 m, 즉 2 cm보다 크면 목표를 거부한다는 점을 설명해 주세요. 작업 공간 제한 안에 있는 목표도 IK가 항상 성공하는 것은 아니라고 분명히 말해 주세요. 마지막 확인 질문은 “범위 안의 목표가 모두 도달 가능한가요?”로 하고 답은 “아니며 IK가 도달 가능성을 추가로 검사한다”로 해 주세요.
```

## 5. Topic과 메시지의 의미

```text
제공된 6주차 요약 자료만 근거로 한국어 1~2분짜리 복습 영상을 만들어 주세요. 주제는 “6주차 Topic 이름만 보고 데이터 흐름 이해하기”입니다.

다음 토픽을 화살표 흐름으로 설명해 주세요: /joy, /target_pose, /gripper_open, /joint_targets, /joint_states, /ee_pose, /safety/torque_enable. 각 토픽의 메시지 타입과 핵심 의미를 짧게 붙여 주세요. 특히 /target_pose는 목표, /joint_targets는 IK가 만든 명령, /joint_states는 서보에서 측정한 관절값, /ee_pose는 측정값에 FK를 적용한 현재 자세라는 차이를 강조해 주세요.

끝에 화면에 /joint_targets와 /joint_states를 나란히 보여 주고 “둘 다 관절값인데 무엇이 다른가요?”라고 질문한 뒤, 하나는 명령이고 하나는 실제 측정값이라고 답해 주세요.
```

## 6. Launch와 ROS 2 패키지 구조

```text
제공된 6주차 요약 자료만 근거로 한국어 1~2분짜리 짧은 영상을 만들어 주세요. 주제는 “Launch 파일이 하는 일과 하지 않는 일”입니다.

week06_ee_control 패키지의 Launch가 joy_node와 실습 노드 다섯 개를 한 번에 시작하는 모습을 보여 주세요. Launch는 프로세스 시작 설정이며 Topic을 직접 연결하지 않는다는 점, Publisher와 Subscriber가 같은 토픽명과 호환 메시지 타입을 사용하면 ROS 2가 통신을 연결한다는 점을 대비해서 설명해 주세요.

device_id는 joy_node가 사용할 SDL 장치 번호이고 start_joy:=false는 Launch가 joy_node를 실행하지 않는다는 뜻이라고 설명해 주세요. 끝에는 “Launch가 Topic 데이터를 중계하나요?”라고 질문하고 아니라고 답해 주세요.
```

## 7. arm_driver, 관절 제한과 속도 제한

```text
제공된 6주차 요약 자료만 근거로 한국어 1~2분짜리 설명 영상을 만들어 주세요. 주제는 “IK 계산 다음에 arm_driver가 하는 일”입니다.

ik_solver가 보낸 /joint_targets를 arm_driver가 받아 관절 이름과 limit_rad 범위를 확인하고, 허용된 목표를 관절별 최대 속도에 맞춰 서보에 전달하는 과정을 보여 주세요. /joint_targets와 /joint_states의 차이, 전체 6개 관절을 요구한다는 점(arm 5개 + gripper)을 설명해 주세요. 상태 발행 50 Hz와 제어 100 Hz는 설정값으로 소개해 주세요.

max_step = max_vel_rad_s × dt 공식을 화면에 표시하고, 속도 제한은 한 주기에 움직일 수 있는 양을 제한한다고 풀어 주세요. 마지막 질문은 “arm_driver가 IK도 계산하나요?”로 하고, IK는 ik_solver가 담당한다고 답해 주세요.
```

## 8. 세 타임아웃과 마지막 자세 유지

```text
제공된 6주차 요약 자료만 근거로 한국어 1~2분짜리 설명 영상을 만들어 주세요. 주제는 “입력 단절 때 세 단계로 멈추는 과정”입니다.

게임패드 메시지가 끊긴 뒤 시간축을 애니메이션으로 보여 주세요: joystick_to_pose는 0.50초 동안 새 /joy가 없으면 새 목표 발행을 멈추고, ik_solver는 0.25초보다 오래된 목표를 사용하지 않으며, arm_driver는 새 관절 목표가 300 ms 동안 없으면 진행 중 이동을 멈추고 마지막 명령 자세를 유지합니다.

이 세 타임아웃은 계층마다 목적이 다르다고 설명해 주세요. 중립 스틱은 /joy가 계속 들어올 수 있어 입력 단절과 다르고, 마지막 자세 유지는 토크 해제가 아니라는 점을 강조해 주세요. 끝에 “타임아웃 후 로봇 토크는 자동으로 꺼지나요?”라고 묻고 아니라고 답해 주세요.
```

## 9. 토크와 실습 안전 절차

```text
제공된 6주차 요약 자료만 근거로 한국어 1~2분짜리 안전 교육 영상을 만들어 주세요. 주제는 “토크 활성화부터 안전한 종료까지”입니다.

실습 순서를 차례로 보여 주세요: 로봇 작업 반경을 비우고 장치와 /joy를 토크 없이 확인하기 → 토크 해제 명령용 별도 터미널 준비하기 → 주변을 다시 확인하고 /safety/torque_enable에 true 보내기 → 작은 조이스틱 입력으로 시험하기 → 종료 때 false를 보내 토크 해제를 확인하기 → 그 뒤 Launch 종료하기.

토크를 켤 때 현재 측정 자세를 첫 유지 목표로 사용한다는 점, 마지막 자세 유지와 토크 해제는 다르다는 점, 토크 해제 시 링크가 내려갈 수 있다는 점을 설명해 주세요. 토크가 켜진 팔을 손으로 억지로 밀지 말라고 명확히 안내하고, 실습 종료 순서를 기억하게 하는 짧은 복습 질문으로 끝내 주세요.
```

## 10. 조교님 구두 퀴즈: 핵심 질문 5개

```text
제공된 6주차 요약 자료만 근거로 한국어 1~2분짜리 구두 퀴즈 영상을 만들어 주세요. 한 명이 조교처럼 질문하고, 잠깐 생각할 시간을 준 뒤 모범 답변이 화면에 나타나는 형식으로 구성해 주세요.

질문은 정확히 다섯 개로 해 주세요: (1) FK와 IK의 입출력은 무엇인가? (2) /target_pose와 /ee_pose의 차이는 무엇인가? (3) /joint_targets와 /joint_states의 차이는 무엇인가? (4) 게임패드 입력 단절 시 0.50초, 0.25초, 300 ms 타임아웃은 각각 어디서 무엇을 하나? (5) 실습 종료 시 토크 해제와 Launch 종료의 올바른 순서는 무엇인가?

답변은 각 1~2문장으로 짧고 정확하게 해 주세요. 소스에 없는 수치나 동작을 만들어 내지 말고, 답을 설명할 때 해당 ROS 노드나 토픽명을 함께 말해 주세요. 마지막 화면에는 기억 공식 “목표 → IK → 서보 → 측정 상태 → FK”를 보여 주세요.
```
